# 油墨換頁動畫與黑白灰配色

2026-09-30

換頁時用墨把畫面蓋過去，再露出新的一頁。四種效果（墨暈、噴漆、潑墨、刷痕）依換頁的類型分配。
另外加一組黑白灰配色，在設定頁切換。四種效果的樣子見
[assets/2026-09-30-ink-transition-demo.html](assets/2026-09-30-ink-transition-demo.html)（用瀏覽器打開，可以點、可以拖進度）。

## 為什麼做

- 現在換頁是瞬間跳過去，沒有任何過場。
- 想試一組黑白灰的配色，又不想直接拿掉現在的紫色。

## 已定案的決定

1. **四種效果都做，依換頁類型分配**（見下表），不是隨機、也不是讓使用者挑。
2. **黑白灰是設定頁的一個選項**，預設仍是紫色；選了什麼記在這支手機裡。
3. **黑白灰只換主色、背景、邊框**。警示（琥珀）、錯誤（紅）、成功（綠）照舊，該注意的東西一樣一眼看得到。
   吉祥物熊熊滾維持紫色，牠的顏色是角色的一部分。
4. **四種效果都是「蓋滿、換頁、露出」**：墨蓋滿整個畫面的那一刻才換頁。試玩頁初版的墨暈是新舊兩頁同時在畫面上，
   放進 App 要同時掛兩頁，捲動位置、固定在底部的分頁列都會打架，所以墨暈也改成蓋滿才換（試玩頁已經跟著改）。
5. **用 WebGL 著色器畫**，不放圖檔、不加套件。形狀全是雜訊算出來的，顏色、起點、長度都是參數。
6. **不動 React Router 的用法**。內建的 `viewTransition` 只在 data／framework 模式有效，App 用的是 `<BrowserRouter>`；
   這次的做法是讓 `<Routes>` 先繼續顯示舊的那一頁，墨蓋滿了再換成新的。

## 哪種換頁播哪一種

| 換頁 | 效果 | 整段長度 |
|---|---|---|
| 底部分頁之間（今日、客戶、頻道、問答、促銷） | 墨暈 | 0.70 秒 |
| 進入或返回內頁（客戶、拜訪、設定、表單…） | 刷痕 | 0.78 秒 |
| 登入、註冊完成、登出 | 潑墨 | 0.95 秒 |
| 設定頁換配色 | 噴漆 | 1.40 秒 |

不播的情況：

- 同一頁裡只換查詢參數或 state（主管端切換分頁、設定頁清掉提示）。
- `replace` 的導頁。這些是轉址（沒登入被送去登入頁、主管的首頁轉到主管端）或流程裡的換步驟（錄音完到整理中），
  不是使用者按了要去別頁。被 401 踢回登入頁、刪除帳號也屬於這一類，照現在的樣子直接換。
- 系統開了「減少動態效果」、分頁在背景、瀏覽器開不了 WebGL：直接換頁，跟現在一樣。
- 上一段還沒播完又換頁：不疊第二段，直接換。

墨從手指按的位置出來；不是按出來的換頁（登入等伺服器回來才換頁、鍵盤操作）從畫面中間偏上出來。
墨的顏色跟著配色：紫色配色是紫色的墨，黑白灰配色是黑到灰的墨；換配色的那一次從舊配色的顏色染到新配色的顏色。

## 做法

```
src/ink/effects.ts      四種效果的名字、長度、哪種換頁播哪一種、墨的顏色、墨暈的時間表（純函式）
src/ink/controller.ts   一段轉場的流程：蓋 → 換 → 等新的畫面出來 → 露出（不碰 DOM，時間與畫布都是外面給的）
src/ink/shaders.ts      四支 fragment shader
src/ink/renderer.ts     WebGL：編譯、畫一格、清掉
src/ink/ink.ts          全 App 共用的那一個 controller，加上 playInk、changeSkin
src/lib/skin.ts         配色的 store：讀寫 localStorage、掛 <html data-skin>
src/components/ink-transition.tsx   <InkOverlay>（畫布）與 <InkRoutes>（包住 <Routes>）
```

**流程**（`controller.ts`）：`play({ effect, colors, atSwap })`

1. 蓋：前半段時間把進度從 0 推到 0.5，每一格請畫布畫。
2. 換：到 0.5 時呼叫 `atSwap`，並通知有訂閱的人。
3. 等：至少停兩格讓新的畫面畫出來；`atSwap` 回傳 Promise 的話等它結束，最多等 1.5 秒。
4. 露出：後半段時間把進度從 0.5 推到 1，清掉畫布。

正在播的時候再叫 `play`，不播第二段，`atSwap` 馬上做。不能播（減少動態效果、分頁在背景、沒有畫布）也是馬上做。
蓋到一半 `requestAnimationFrame` 停了（分頁被切到背景），有一個計時器保底把頁面換過去，不會卡在舊的那一頁。

**換頁**（`<InkRoutes>`）：包住 `<Routes>`，永遠傳 `location` 給它。網址變了、而且該播動畫時，先把舊的 location 留著繼續顯示，
叫 `play`，蓋滿時放開，`<Routes>` 才換成新的那一頁。不該播的時候什麼都不留，跟原本一樣馬上換。
所有 `<Link>`、`navigate()`、瀏覽器上一頁都會經過這裡，各頁不必改。

**要先蓋再做事的三個地方**直接叫 `playInk(effect, 要做的事)`：

- 登入、註冊、GitHub 登入成功：`signIn` 之後登入頁自己會變成轉址（畫面變空白），所以要等墨蓋滿才 `signIn` 和換頁。
- 登出：同樣的理由，蓋滿才登出。
- 換配色：蓋滿才換 `<html data-skin>`。

**畫布**（`<InkOverlay>`）：一張固定在最上層、跟 App 同寬（`max-w-md`）的 canvas。平常隱藏；播的時候蓋住畫面並擋掉點擊，
免得按到墨底下看不到的東西。解析度最多 1.5 倍；一段播下來平均每格超過 30 毫秒就降一級（1.5 → 1 → 0.75），
再慢就這次打開不再播。

**配色**（`lib/skin.ts` 與 `index.css`）：`<html data-skin="mono">` 時覆蓋主色、背景、邊框那幾個變數。
模組載入時就掛上去，第一個畫面就是對的顏色。

## 測試

vitest 的環境是 node，沒有瀏覽器。

- `effects.test.ts`：每一種換頁分到哪個效果；墨的顏色跟著配色；墨暈的時間表在 0.5 時整個畫面都蓋得到、在 0 和 1 時畫面上沒有墨。
- `controller.test.ts`：用假的時鐘和假的畫布跑一段，確認順序是蓋、換、等、露出；`atSwap` 只叫一次；
  等 Promise；不能播時馬上做；播到一半再叫不疊；保底計時器會把頁面換過去。
- `skin.test.ts`：預設紫色；存過黑白灰就讀得回來並掛上 `data-skin`；存不進去也照樣換。

著色器與實際換頁靠打開 App 看：在瀏覽器裡讀畫布的像素，確認四種效果在換頁那一刻每個像素都不透明、開始和結束時完全透明。

## 不在這次範圍

- 新舊兩頁同時在畫面上的轉場（View Transitions API）。
- 返回時把動畫方向反過來。
- 讓使用者關掉動畫或自己挑效果的設定。
- 深色模式。黑白灰是淺色底的另一組主色，不是深色模式。
- 音效。
