# 點站就騎過去、個人頁的獎牌與圖表

2026-10-09

兩件事一起做：首頁路線改成「點一站，熊熊滾就騎過去」，不用錄音、不用送出拜訪；新增個人頁，放事蹟數字、
可以直接在牆上轉的立體獎牌，和兩張會長出來的圖表。獎牌只算點過的站，所以兩件事接在一起：評審在首頁點幾站，
個人頁就解鎖幾面。

個人頁的樣子以這份 demo 為準（瀏覽器打開就會動）：
[assets/2026-10-09-personal-page-demo.html](assets/2026-10-09-personal-page-demo.html)。

## 為什麼做

- 原本一站要錄音、確認送出拜訪才算跑完，熊熊滾才會騎到下一站。展示時沒辦法一站一站錄，評審看不到熊騎過去。
  而且拜訪時間用真實時間、行程用系統日（固定在決賽日 10/28），10/28 之前在正式站確認送出也不會打勾。
- 業務想看自己跑過哪些藥局、哪家賣最多；評審需要一個記得住的畫面：點一站、解鎖一面金牌，拿起來轉。

## 已定案的決定

1. **點站的圓鈕就騎過去**，同時彈出小卡。往回騎、跳站都可以，順序沒有限制。
2. **點過的站算「到過」**：打勾，跟跑完的站同一個樣子；**路線順序與預計時間不動**。不用錄音或送出拜訪；確認送出拜訪照舊也算跑完。
3. **到過的紀錄存在伺服器**，主管頁看得到；IT 重置示範業務的行程時一起清掉。
4. **回首頁自動騎一次拿掉**，一律點了才騎。點停著的座騎重播最後那一段，保留。
5. **小卡預覽「進門前三分鐘」**，加上原本的「為什麼排這家」與最多三則備忘，最下面是「開啟拜訪準備」。
6. **進門前三分鐘不再寫競品那一句**（客戶檔案與小卡都是）。業務錄音時講到競品，確認時把他講的話記成一則備忘，
   放在「下次去要記得」，跟要帶的、講過的同一類。客戶檔案的「競品紀錄」一區照舊。
7. **個人頁的入口是首頁左上角的名字**（原本進帳號設定）；個人頁右上角的齒輪進帳號設定。只有業務有這一頁。
8. **三格事蹟數字**：近一年拜訪、名下客戶、近一年業績。不寫「去過幾家」，免得跟獎牌的「跑過幾家」打架。
9. **獎牌兩類各三級（銅、銀、金），只算首頁點過的站**：跑過的藥局 1／3／5 家，跑過的縣市 1／2／3 個。
   以前的拜訪不算：示範業務一年拜訪過名下全部 53 家，算進來的話一打開就全部解鎖。
10. **獎牌是立體的（three.js）、沒有緞帶，直接在牆上轉**，不用彈出畫面。平常輕輕左右擺；拖著往上下左右轉，
    點一下翻一圈。跑不動 WebGL 時退回平塗的獎牌。
11. **兩張圖會長出來**：賣最多的藥局前五名（長條）、近六個月每月業績（直條）。捲到才播，一根接一根，稍微衝過頭再彈回，
    數字從 0 跳到實際的值。
12. **解鎖的那一刻**：首頁點站剛好解鎖時，底下跳一行「解鎖銀牌：跑過 3 家藥局」，點了進個人頁；
    個人頁上新解鎖的那面亮一圈、快轉幾圈，每一面只演一次。

## 資料

`models.py` 改了，`schema_version` 的指紋跟著變，部署時重建資料庫（跟以往一樣）。

### `stop_arrival`：點過的站

| 欄位 | 內容 |
|---|---|
| `itinerary_id` | 哪份行程，行程刪掉時一起刪 |
| `customer_id` | 哪一家 |
| `first_at` | 第一次點的時間，算獎牌的解鎖日期 |
| `last_at` | 最後一次點的時間，決定熊熊滾停在哪一站 |

- 主鍵 `(itinerary_id, customer_id)`。再點一次只更新 `last_at`。
- 拿掉一站時不刪這一列：點過就算跑過，獎牌不會因為改路線掉回去。
- IT 重置示範業務的行程會刪掉那份行程（行程編號換新），這些列跟著刪，獎牌歸零。

### `customer_note`：多一種 `competitor`（競品）

- `NOTE_KINDS` 加 `competitor`。它跟「講過的」一樣一定有日期（拜訪日）；`told_has_date` 約束原本就是「只有要帶的可以沒有日期」，不用改。
- 確認拜訪時（`customer_notes.notes_from_visit`），`competitor` 欄位的每一項寫成一則：有細節寫「名稱：細節」，
  沒有就寫「提到名稱」，超過 200 字截掉。
- 「下次去要記得」的排法不變：要帶的在前，其他照建立的先後。手寫的「記一筆」照舊只有要帶的、講過的兩種。
- 日曆只放要帶的、講過的（`month_notes` 濾掉競品）。
- 示範資料：在 `catalog.NOTES` 給示範業務今天路線上的幾家各加一則競品備忘，跟其他示範備忘一樣不掛拜訪
  （掛了拜訪會讓 `next_notes` 把更早的手寫備忘藏起來）。

## 行程：`services/itinerary.py`

- 行程的每一站多回 `arrived_at`（這份行程裡最後一次點的時間，沒點過是 null）。
- **到過的站狀態是 `done`，但留在原本的位置、時間照原本排的算**，不像確認送出的拜訪那樣搬到最前面、從它重算後面的時間。
  `next` 是第一個既沒跑完也沒到過的站。行程的 `done` 數也算到過的站。
- 主管頁照 `status` 畫打勾與進度；`team_itineraries.rep_map` 判斷跑完的那一段也要算到過的站。
- 點站不改行程的版本，只改 `updated_at`：主管頁照現在的做法收到 `itinerary` 事件，別的評審手上同一版的行程照樣可以改（三顆按鈕、換交通方式、套用提案、調整清單的「完成」不會因為有人點站而 409）。

## API

| 方法與路徑 | 用途 |
|---|---|
| `POST /api/itinerary/today/stops/{customer_id}/arrive` | 點站。回新的行程與 `unlocked`（這次解鎖的獎牌，通常是空的）。不檢查也不改版本（只改 `updated_at`），點了一定成功；不在今天行程上的客戶回 404 |
| `GET /api/customers/{customer_id}/brief` | 小卡用：`highlights`（進門前三分鐘）與 `notes`（下次去要記得）一次回來。權限跟客戶檔案一樣（`customer_profile`） |
| `GET /api/me` | 個人頁：名字、區、名下客戶數，三格事蹟數字，六面獎牌，前五名藥局，近六個月業績 |

- 跟其他路線的 API 一樣，業務由 token 決定（`acts_as_user_id or id`）；主管與 IT 打 `arrive` 與 `me` 回 403。
- `GET /api/me` 的內容：
  - `stats`：近一年確認過的拜訪次數、名下客戶數、名下客戶近一年的進貨金額。「近一年」＝系統日往前 365 天。
  - `medals`：每面一筆 `{kind: "stores" | "cities", tier: 1–3, need, have, unlocked_on}`。`have` 是這位業務所有行程裡
    點過的不同客戶數（或不同縣市數），`unlocked_on` 是點到第 `need` 家（第 `need` 個縣市）那一天（照 `first_at`），沒解鎖是 null。
    門檻寫成常數 `MEDAL_TIERS`。
  - `top_customers`：名下客戶近一年進貨金額的前五名（名稱、金額）。
  - `monthly`：近六個月（含這個月）每月的進貨金額；這個月多回 `through`（系統日），畫面上畫淡色並寫「算到 10/28」。

## 首頁

### 點站就騎

- **熊熊滾停的位置**：最後點的那一站（`arrived_at` 最晚的，而且還在路線上）旁邊；今天還沒點過就停在路線最上面
  「從辦公室」那顆膠囊旁邊。區處沒有位置（`office_start` 是 false）時停在第 1 站旁邊，點第 1 站不騎、只開小卡。
- **點一顆站的圓鈕**：熊從停的位置騎到那一站，同時彈出小卡，並送 `arrive`。點熊已經停著的那一站只開小卡。
  - 騎的座騎：那一站的縣市 × 原本排好到那一站的交通方式（`stop.travel_mode`）。跨縣市照樣半路冒煙換車，出發縣市是熊原本停的那一站
    （辦公室出發用 `start_city`）。騎過的照樣送 `vehicles/rides`。
  - 路徑：相鄰往下的一段照原本的彎度（經過兩站中間的膠囊）；往回或跳站的一段從起點直接彎到終點（控制點在兩顆圓鈕中點），
    時間一樣約 3 秒。畫面上量兩顆圓鈕的位置，`components/rides/ride-on-route.tsx` 的 `measure` 改成可以量任兩站。
  - 騎到一半又點了別站：這一段直接跳到終點，再從那裡騎去新點的那站。
- **到過的站**：打勾、圓鈕變成跑完的樣子；「出發」泡泡移到第一個還沒到過的站。
- **全部到過**：最後一段騎完，座騎淡出，熊熊滾在收工旗子旁跳 `yay`（跟原本全部跑完一樣）。
- 點停著的座騎：重播最後那一段（倒數第二個點的站或辦公室 → 最後點的站）。
- 拿掉：`legToPlay` 與「播過哪幾段」的 localStorage 記錄（`lib/ride-memory.ts` 只留騎過的座騎送不出去時的佇列）。
- **減少動態效果**：不移動，熊熊滾直接停到點的那一站旁邊；小卡、打勾、騎過的記錄照常。

### 小卡

由上到下：店名、時間與第幾站（到過的加「已到過」）、為什麼排這家、**進門前三分鐘**（最多五句）、下次去要記得（最多三則，
競品備忘標「競品」）、「開啟拜訪準備」（到過的站也是這顆）。小卡打開時才拿 `brief`，回來之前兩區是灰色佔位條。

### 解鎖提示

`arrive` 回的 `unlocked` 不是空的，就在首頁底下跳一行「解鎖銀牌：跑過 3 家藥局」（兩面一起解鎖寫兩面），4 秒後收起；
點了進個人頁。

### 進門前三分鐘：`services/customer_profile.py`

- 拿掉「M/D 拜訪提到競品 X」那一句；`signals` 照舊加 `competitor`（談判卡找切入點要用）。
- 其他句子、上限五句、順序不變。

## 個人頁：`/me`

- 入口：首頁頁首的名字（`pages/today.tsx`）改連到 `/me`，頭像照舊換狀態。主管、IT 開 `/me` 轉去帳號設定。
- 頁首：返回、「個人頁」、右上角齒輪（帳號設定）。
- 由上到下：大頭照（熊熊滾）、名字、「北區 · 業務 · 名下 53 家客戶」；三格事蹟數字；獎牌牆；賣最多的藥局；每月業績。
  評審代理時，個人頁是示範業務的（大頭照旁寫林昱辰），名字下面多一行「示範業務的個人頁」。

### 獎牌牆

- 兩列：「跑過的藥局 · 3 家」「跑過的縣市 · 2 個縣市」，各三面（銅、銀、金），右上角「4 / 6」。
- 每面下面兩行：門檻（「5 家」）與狀態（「10/28 解鎖」或「還差 2 家」）。
- 立體獎牌（`components/me/medal-wall.tsx`）：
  - 一張 WebGL 畫布蓋在獎牌牆上，每一面畫在自己那一格（scissor），只開一個 WebGL。
  - 獎牌：金屬圓盤、外圈、一圈壓紋（`InstancedMesh`），正面是那一類的圖示（藥局是十字、縣市是地標），
    背面是門檻與解鎖日期；沒解鎖的是灰色霧面，正面是鎖、背面寫「差 2」。
  - 平常輕輕左右擺（每面相位不同）；拖著轉（左右繞直立的軸、上下繞水平的軸），放手保留轉速慢慢減，慢下來後回到擺動；
    幾乎沒動就放開算點一下：解鎖的翻一圈，沒解鎖的抖一下並跳出「再跑 2 家藥局就拿到金牌」。
  - 新解鎖、這支手機還沒看過的：外圈亮一圈、快轉幾圈。看過的記在 localStorage（`meddemo:medals-seen:<業務>`，
    鍵含解鎖日期，IT 重置後會再演一次），讀寫包 try/catch。
  - `three` 只在個人頁用：`/me` 用 `React.lazy` 載入，首頁不多載。環境光用 `RoomEnvironment`。
  - 跑不動 WebGL（建立 renderer 失敗）或 three.js 載不下來：每一格改放平塗的 SVG 獎牌（同樣的顏色與圖示），點了照樣說還差多少。
  - 減少動態效果：不擺、解鎖不快轉；拖著轉照常。
- 顏色：銅 `#CD8A4B`、銀 `#BCC2CC`、金 `#FFC93C` 各一組（外圈、面、內圈、圖示），沒解鎖是灰紫。跟熊熊滾一樣不用 emoji。

### 圖表

- 賣最多的藥局：五列，每列上面是店名、下面是長條（14px 高、尾端 4px 圓角），數字在長條尖端，跟著尖端走。
- 每月業績：六根直條（22px 寬、頂端 4px 圓角），格線 0／100／200／300 萬，月份在下面；只標最高的那個月與這個月的數字，
  其他滑過（或點）看。這個月畫淡色，下面寫「10 月只算到 10/28」。
- 單一系列，用主色，不放圖例；文字一律用文字色。
- 動畫：圖表捲進畫面（`IntersectionObserver`，捲動容器是頁面）才播，每次打開頁面播一次；一根接一根（間隔約 0.1 秒），
  0.9 秒長出來、稍微衝過頭再彈回；數字 0.9 秒從 0 跳到實際的值。減少動態效果時直接畫好。

## 出錯時

- `arrive` 送不出去：熊照樣騎、小卡照樣開，小卡下面一行「沒連上，這一站還沒記到」，不打勾、不跳解鎖。不做離線補送。
- `brief` 拿不到：小卡少那兩區，其他照常。
- `GET /api/me` 拿不到：顯示「個人頁暫時載入不了」與「再試一次」。
- three.js 載不下來或沒有 WebGL：平塗獎牌（見上）。
- 量不到圓鈕的位置：不騎，熊直接停到點的那一站旁邊。

## 測試

後端（pytest）：

- `arrive`：第一次點建一列、再點只改 `last_at`；不在今天行程上的客戶 404；主管、IT 403；行程版本不變、主管頁照樣收到 `itinerary` 事件。
- 行程：到過的站 `done`、位置與時間不變；`next` 跳過到過的站；`done` 數；主管頁的 `rep_map` 跑完的段。
- IT 重置後點過的紀錄清空。
- 獎牌：家數與縣市數、門檻、解鎖日期照 `first_at`；拿掉一站之後獎牌不掉；`unlocked` 只回這次新解鎖的。
- `GET /api/me`：三格數字、前五名、六個月與這個月的 `through`（用灌好的測試資料庫對數字）。
- 進門前三分鐘沒有競品那句，`signals` 還有 `competitor`；`brief` 的權限。
- 確認拜訪寫出競品備忘（有細節、沒細節、超過 200 字）；日曆不列競品備忘。

前端（vitest，`renderToStaticMarkup` 與純函式）：

- 從停的位置騎到任一站：往下相鄰、往回、跳站、跨縣市、從辦公室、點熊停著的那站不騎；停的位置（最後點的、拿掉之後、沒點過、沒有辦公室起點）。
- 小卡：進門前三分鐘、競品備忘的標籤、送不出去的那一行。
- 獎牌牆：四種狀態的字、「4 / 6」、平塗的退路；看過的記錄（壞掉的 JSON、localStorage 丟例外）。
- 圖表：前五名的長度比例、這個月淡色與註明、只標兩個數字。

實際打開 App：照之前的做法從 worktree 起一套隔離環境，用 headless Chrome 分短段截圖（390 寬，淺色與深色）：
點站騎過去（往下、往回、跨縣市進新竹）、小卡、首頁的解鎖提示、個人頁上半部與圖表、獎牌轉到一半、新解鎖的那一面。

壓力測試：模擬 20 位評審同時代理林昱辰，一直點站、開小卡、開個人頁（`backend/scripts/stress_arrivals.py`，跟頻道的壓力測試同一種寫法）。
不能有 500，主管頁最後的進度要等於點過的不同站數。

## 已知限制

- 點站不檢查人是不是真的在那裡，也不管順序。
- 到過的站不重算後面的時間，預計時間照早上排的。
- 錄音確認送出那條路照舊只認「拜訪日＝系統日」，10/28 前在正式站不會因為送出拜訪而打勾；點站不受影響。
- 評審共用示範業務，點過的站與獎牌會累加，要靠 IT 重置。新解鎖演過了沒記在瀏覽器，換手機會再演一次。

## 不在這次範圍

- 其他種類的獎牌（業績、座騎圖鑑、拜訪習慣）。
- 主管、IT 的個人頁。
- 點站的離線補送。
- 音效、分享獎牌。

## 分階段做
