# 設定跟著帳號存在伺服器

2026-10-02

接在〈大頭貼與字體大小〉（2026-10-01-avatars-text-size-design.md）之後。那份文件把配色與字體大小定成「記在這支手機上，
跟帳號無關」；James 10/2 說所有設定都要上雲：換一支手機、換一台電腦登入，看到的要是自己選的。

同一天發現大頭貼雖然本來就存在伺服器的資料庫，部署時卻會不見：資料表一改，部署流程就重灌假資料（.github/workflows/ci-cd.yml），
重灌只留自建帳號與第三方登入的綁定，大頭貼跟著清掉。10/1 17:23 那次部署就是這樣，所以看起來像是「存在本地」。

## 已定案的決定

1. **配色與字體大小存在伺服器，以伺服器為準**。手機裡照舊留一份，只是為了下次打開在畫面出來前就先套上，不閃一下預設的樣子。
2. **重灌時留下每個帳號的設定**：大頭貼、配色與字體大小、自己選的在線狀態（「請勿打擾」這類）。公司帳號的也留，工號重灌後不變。
3. **同一個帳號的其他裝置即時跟著換**：用既有的 WebSocket 發事件，只送給同一個帳號的連線。

## 資料

`user_preference`，一個帳號最多一列，第一次存設定時建立：`user_id`（PK，FK `app_user`，ON DELETE CASCADE）、
`skin`（light／dark）、`text_size`（standard／large／xlarge）、`updated_at`。沒有這一列就是「還沒存過」。

## API

| 方法 | 路徑 | 內容 |
|---|---|---|
| GET | `/api/preferences/me` | `{skin, text_size}`；還沒存過兩個都是 `null` |
| PATCH | `/api/preferences/me` | 只帶要改的欄位，沒帶的不動；回存好之後的整份 |

- PATCH 是一句 upsert：兩支手機同時第一次存不會撞主鍵；各改一項不會互相蓋掉。
- 存好就發 `{"type": "preferences", "user_id": …}`。WebSocket 只轉給 `user_id` 相同的連線（不帶內容），
  別人連「這個帳號改了設定」都不會知道。

## 手機上（frontend/src/lib/preferences.ts）

- **登入後**拿一次，套上伺服器的設定。**還沒存過**（兩個都是 `null`）就把這支手機現在的設定存上去：
  換成存伺服器之前，大家選的深色、大字都在手機裡，第一次登入就搬上去，不會回到預設。
- **自己選的**先換畫面（配色照舊播噴漆），再 PATCH。一次只送一個請求，送的期間又選了，送完接著送。
- **存不上去**（沒訊號）就記在手機裡（`localStorage` 的 `meddemo:preferences-pending:{帳號}`），
  WebSocket 重連、下次打開或再選一次時再送；送上去之前，伺服器的舊值不會把剛選的蓋回去。
- **收到 `preferences` 事件或重連（resync）**就重拿一次。自己剛換配色時，自己這支也會收到事件：
  伺服器回的跟剛存上去的一樣就不再套一次，不然噴漆還沒蓋滿畫面，顏色就先換掉了。
- 重拿還沒回來時又選了，那次重拿作廢。登出、換人時清掉；上一個人沒送成功的留在手機裡，只有同一個人登入才送。
- 套上伺服器的設定是直接換，不播噴漆。

## 重灌（data/seed/seed.py）

`KEPT_SETTINGS` 列出跟著帳號留下來的表：`user_avatar`、`user_preference`、`user_presence`。重建之前整張讀出來，
自建帳號放回去之後再放回去；帳號已經不在的跳過。一張表放不回去（舊資料不合新的資料表）只放棄那一張，灌資料照常往下走。
大頭貼的版本原樣留著，手機上的網址重灌後還能用。

## 個資

隱私權頁補上：配色與字體大小存在帳號上、只有自己看得到、保留到刪除帳號為止；刪帳號時一起刪。

## 測試

- pytest：還沒存過是 `null`；只改一項另一項不動；不認得的值 422；要登入；事件只送給同一個帳號的連線；刪帳號一起刪；
  重灌留下大頭貼、設定、選的狀態，帳號不在的跳過；一張表放不回去不影響其他張。
- vitest：還沒存過就把手機的存上去；以伺服器為準；存不上去留著、重拿前先送；舊的重拿作廢；
  自己剛換的不再套一次；別的裝置改了跟著換；一次只送一個；換人不送上一個人的。

## 不在這次範圍

- 新人第一週的勾選、首次使用引導看過沒有、路線的暫緩與插入下一站、頻道停在哪一個：這些是進度與畫面位置，不是設定，照舊記在手機裡。
- 大頭貼改放物件儲存（GCS）：照片本來就在 Google Cloud 上的資料庫裡，問題出在重灌，不在存放的地方。
