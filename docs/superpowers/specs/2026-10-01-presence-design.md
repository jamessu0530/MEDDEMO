# 在線狀態與即時連線

2026-10-01

頻道裡看得到誰在線上，每個人可以自己決定要顯示什麼狀態，跟 Teams 一樣。
同一條 WebSocket 順便把「頻道有新訊息」推給手機，頻道不必再每 3 秒輪詢一次。
接在〈頻道與 AI 主理記憶〉（2026-09-28）之後；那份文件把即時連線列在「第一版不做」，這份把它補上。

## 已定案的決定

1. **狀態跟 Teams 一樣**：自動判斷「有空／離開／離線」，也可以手動選有空、忙碌、請勿打擾、馬上回來、
   顯示為離開、顯示為離線；「重設狀態」回到自動。手動選的一直維持到自己改掉。
2. **四個地方看得到**：頻道頁的頁首（在線的人疊成一排頭像，點了看成員清單）、別人每則訊息旁的頭像、
   頻道列表每一列的「N 人在線」、自己的頭像（首頁頁首與設定頁，點了換狀態）。
3. **頭像是名字縮寫**：中文取名字最後兩個字（林昱辰 → 昱辰），英文取前兩個字母（James → JA，James Su → JS）。
   底色依帳號固定從五個顏色裡挑一個。不做照片上傳。
4. **一條 WebSocket 同時送狀態與新訊息通知**，斷線時退回輪詢。

## 狀態怎麼算

一律在後端算，`services/presence.py` 的 `display_status(choice, last_seen_at, last_active_at, now)`：

| 條件 | 顯示 |
|---|---|
| 選了「顯示為離線」，或從沒連過、已登出 | 離線 |
| 最後一次心跳超過 5 分鐘 | 離線 |
| 有手動狀態 | 那個狀態（有空、忙碌、請勿打擾、馬上回來、離開） |
| 45 秒內有「正在用」的心跳 | 有空 |
| 其他（連著但閒置、畫面在背景、剛斷線） | 離開 |

- 手機每 20 秒送一次心跳，帶 `active`：畫面在前景，而且 5 分鐘內碰過螢幕（點、打字、捲動）。
  `active` 的心跳更新 `last_seen_at` 與 `last_active_at`，不是的只更新 `last_seen_at`。
- **「離開」不靠另外送一則「我閒置了」**：`last_active_at` 超過 45 秒自然就是離開。
  同一個帳號開兩個分頁，一個在背景、一個在用，也不會在有空和離開之間來回跳。
- 斷線（手機切到別的 App、進電梯）先顯示離開，5 分鐘後才變離線。登出立刻變離線。
- 停用的帳號一律離線。
- 時間用真實時間，不是展示日（as_of）：狀態是「現在」的事。

**隱私**：伺服器只送算好的狀態，不送最後上線時間。選了「顯示為離線」的人，在別人眼中跟真的離線完全一樣。
自己看自己時，看到的是自己選的那個（例如「顯示為離線」）。

所有人都在全國頻道，所以每個人本來就看得到每個人；狀態不另外分誰看得到誰。

## 頻道成員

頻道沒有成員名單（誰看得到是用組織樹算的）。成員照**組織位置**算：

- 帳號的位置（自建與第三方登入的帳號用代理那位業務的位置）在頻道路徑底下（含本身）就是成員。
  全國：全公司（含 IT）；整區、地點、客戶討論串：那一區的人；小組：主管與組員。
- 客戶討論串另外加上負責人與他的主管（負責人被 IT 調到別區時，跟頻道的看得到規則一致）。
- IT 坐在根節點，只算全國頻道的成員。IT 看得到各組的頻道，但不是成員，跟輸入框上「只有陳建宏小組看得到」的說法一致。
- 停用的帳號不算；封存的小組頻道沒有成員。

成員一定看得到頻道（位置在頻道路徑底下，`Scope.can_see` 一定成立），反過來不一定（IT）。

頻道列表的「N 人在線」是成員裡狀態不是離線的人數，**不算自己**。

## 資料模型

`user_presence`，一個帳號最多一列，第一次連線或選狀態時建立：

- `user_id`：PK，FK `app_user`（ON DELETE CASCADE，自建帳號刪除時一起刪）
- `choice`：手動選的狀態，NULL 是自動。`available`／`busy`／`dnd`／`brb`／`away`／`offline`
- `last_seen_at`：最後一次心跳或斷線的時間，登出時清成 NULL
- `last_active_at`：最後一次「正在用」的心跳

最後上線時間存 Postgres 不存 Redis：全公司十幾個帳號，每 20 秒寫一列不是負擔，狀態也只要從一個地方算。
手動狀態更不能只放 Redis：Redis 重啟，選了「顯示為離線」的人就會突然被看見。

## WebSocket：`/api/ws`

`api/presence.py`。每條連線自己訂閱 Redis 的事件頻道，不另外開背景程序；連線斷了，訂閱跟著結束。

**連線**：

1. 連上後 10 秒內要送 `{"type": "auth", "token": "…", "active": true}`。token 不放網址：網址會進 Nginx 與 Cloudflare 的紀錄。
   token 不對、過期、被別的裝置頂掉或帳號停用，關閉碼 `4401`；10 秒沒送，`4408`。
2. 通過後記一次心跳、訂閱事件，送 `{"type": "ready", "user_id": "U01"}`，
   接著送全部狀態 `{"type": "presence", "full": true, "statuses": {"U01": "available", …}}`（只列不是離線的人）。
3. 同一個帳號在同一台 API 最多 5 條連線，第 6 條關閉碼 `4429`。

**手機送給伺服器**：`{"type": "ping", "active": true|false}`，每 20 秒一次，`active` 變了馬上送一次。
每次心跳都重新驗 token（登出、改密碼、被頂掉的那條連線就會被關掉），5 秒內重複的心跳不寫資料庫。

**伺服器送給手機**：

- `{"type": "presence", "full": false, "statuses": {"M01": "busy", "U02": "offline"}}`：有人狀態變了。
  每條連線記得上次送過什麼，每 10 秒、或收到狀態事件時重算一次，只送有變的。
- `{"type": "message", "channel_id": 12}`：這個頻道有新訊息。只送給看得到這個頻道的人。
  不帶訊息內容：手機收到後用原本的 `GET /api/channels/{id}/messages?after=` 去拿，
  權限檢查與訊息格式都沿用原本的程式，斷線漏掉的通知重連後也補得回來。

**事件**（Redis 發布／訂閱，頻道名稱帶 Redis 的庫號，兩份測試同時跑不會互相收到）：

- `{"type": "message", "channel_id": …}`：`POST /api/channels/{id}/messages` commit 之後發。
  之後背景工作寫的 AI 回答、風險通報也照這樣發。
- `{"type": "presence"}`：有人選了狀態、登出、刪帳號，或心跳讓他的狀態變了（例如從離開回到有空）。
  時間到了才變的（離開 → 離線）不發事件，靠每條連線 10 秒一次的重算。
- 發不出去（Redis 掛了）只記 log，不影響發言：手機在連線時每 30 秒還是會輪詢一次。

## HTTP API

| 方法 | 路徑 | 內容 |
|---|---|---|
| GET | `/api/presence/me` | `{choice, status}`：自己選的與別人看到的 |
| PUT | `/api/presence/me` | `{choice}`，`null` 是重設狀態；回 `{choice, status}` |
| POST | `/api/presence/ping` | WebSocket 連不上時的心跳，`{active}`；回全部狀態 `{statuses}` |
| GET | `/api/channels/{id}/members` | 成員 `[{id, name, status}]`，依名字排；看不到的頻道 404 |

`ChannelItem` 多一個 `online`：成員裡不是離線的人數，不算自己。登出（`POST /api/auth/logout`）時清掉心跳並發狀態事件。

## 部署

- `frontend/nginx.conf` 多一段 `location = /api/ws`：HTTP/1.1、`Upgrade`／`Connection` 標頭，`proxy_read_timeout 120s`。
- `vite.config.ts` 的開發代理多一條 `/api/ws`（`ws: true`），放在 `/api` 前面。
- Cloudflare 與 K3s 的 Traefik 預設就支援 WebSocket。Cloudflare 閒置 100 秒會斷線，20 秒一次的心跳夠用。
- 部署時舊的 API Pod 被換掉，連線會斷，手機自己重連。
- `models.py` 改了，`schema_version` 的指紋跟著變，部署時會重建資料庫（跟以往一樣）。

## 畫面

- **`components/ui/avatar.tsx`**：shadcn 的 Avatar（`radix-nova` 樣式），含 `AvatarBadge`、`AvatarGroup`、`AvatarGroupCount`。
- **`components/user-avatar.tsx`**：縮寫、底色與狀態點。狀態點用顏色加圖示，不只靠顏色分辨：
  有空綠底勾、忙碌紅點、請勿打擾紅底橫線、馬上回來與離開黃底時鐘、離線灰框。
- **頻道頁**：頁首右邊是除了自己以外在線的人（最多三個頭像，再多顯示「+N」），沒人在線就是一個成員圖示。
  點了打開成員清單，依狀態分組（有空、忙碌、請勿打擾、馬上回來、離開、離線），自己標「你」。
  別人每則訊息左邊放頭像與狀態點。連著的時候收到通知就拿新訊息，另外每 30 秒保險輪詢一次；斷線時回到每 3 秒。
- **頻道列表**：每一列第二行「最近 10/01 09:30 · 3 人在線」。收到新訊息通知或有人狀態變了，3 秒後重新載入一次。
- **自己的頭像**：業務首頁頁首的名字左邊、主管端與組織管理頁的頁首右邊，點了打開狀態選單；
  設定頁最上面多一段「狀態」，說明「選『顯示為離線』，別人看到的你是離線，但你照常可以用」。
- **紅點**：收到新訊息通知就重問一次未讀數，原本每分鐘一次的輪詢照舊。

`lib/realtime.ts` 管連線：登入後連、登出時斷；斷線後 1、2、5、10、30 秒重連，切回前景或恢復網路時馬上重連；
關閉碼 `4401` 時如果 token 已經換了（改過密碼）就用新的重連，不然停下來，等之後的請求收到 401 再導回登入頁。
連不上的期間每 20 秒改用 `POST /api/presence/ping`。重連成功時發一個 `resync`，頻道頁與紅點去補漏掉的訊息。

## 測試

- **狀態規則**（pytest）：`display_status` 的每一列；登出、停用、刪帳號都是離線；選了「顯示為離線」別人看到離線、
  `/api/presence/me` 看到自己選的。
- **成員**：小組頻道是主管與組員；整區不含 IT；全國含 IT；客戶討論串含被調到別區的負責人；封存的小組頻道沒有成員；
  看不到的頻道 404。`online` 不算自己、不算離線與「顯示為離線」的人。
- **WebSocket**：token 錯誤 `4401`；連上後收到 `ready` 與含自己的完整狀態；別人選了忙碌，收到只含他的變動；
  發言後看得到的人收到 `message`，看不到的人收不到。
- **前端**（vitest）：名字縮寫、狀態 store 的完整與部分更新、連線的驗證順序、心跳、重連與退回 HTTP 心跳。

## 不在這次範圍

- 照片頭像、狀態訊息（「在大安區拜訪，下午回訊」）、手動狀態的到期時間。
- 請勿打擾擋通知：系統還沒有推播通知，請勿打擾只是顯示。
- 把訊息內容直接放進 WebSocket、輸入中提示、已讀回條。
- 背景工作寫訊息時發事件：現在只有 `POST /api/channels/{id}/messages` 會寫訊息，第 3 階段（AI 回答、風險通報）做的時候一起加。
