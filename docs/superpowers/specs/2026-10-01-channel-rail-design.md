# 頻道改成 Discord 的左右兩欄，經理可以開文字頻道

2026-10-01

頻道頁改成 Discord 手機版的樣子：左邊一條直欄放頻道，右邊是選中那個頻道的面板，列出對話、記憶看板、
照片與檔案，以及這個頻道底下的文字頻道或客戶討論串。整區與全國頻道底下可以再開「文字頻道」，
由那一區的經理（主管）開，全國只有 IT 能開。接在〈頻道與 AI 主理記憶〉（2026-09-28）與
〈在線狀態與即時連線〉（2026-10-01）之後，權限、記憶、在線狀態都沿用那兩份文件。

## 為什麼做

- 現在的頻道是兩頁：先在列表選頻道，進去才看得到對話與記憶看板；客戶討論串、照片搜尋又各是一頁。
  大家用慣 Discord，左邊選、右邊直接看到這個頻道有什麼，少點好幾次。
- 頻道全部跟著組織樹自動產生，「新品上市」「補貨問題」這種跨小組、要整區一起討論的主題沒有地方放，
  只能全部擠在整區頻道裡，熊熊滾整理記憶時也混在一起。

## 已定案的決定

1. **左欄放頻道，右欄放這個頻道的功能**：左欄是全國、各區、各小組、地點；右欄是對話、記憶看板、照片與檔案，
   以及底下的文字頻道（全國與區）或客戶討論串（地點）。
2. **經理開的頻道開在區裡面，出現在右欄**，跟 Discord 的伺服器管理員在伺服器裡開文字頻道一樣；左欄不會越開越長。
3. **誰能開**：區裡是那一區的在職主管與 IT；全國只有 IT。小組、地點底下不能開。業務與自建帳號都不能開。
4. **開好的頻道整區（全國的是全公司）都看得到、都能發言**，有自己的記憶看板，重點照樣往上傳到區、再到全國。
5. **只做文字**：語音、通話、直播都不做。
6. **畫面不用表情符號**，圖示一律用 lucide。

## 文字頻道

### 資料

`channel` 表多一種 `kind = 'topic'`，不另開一張表：訊息、附件、已讀、熊熊滾、記憶、往上傳、照片搜尋、在線狀態
都是跟著 `channel.id` 走的，直接沿用。

- 新欄位：
  - `name`：文字頻道的名稱，1～20 字（前後空白去掉後算）。其他種類的頻道是 NULL，名稱照舊從組織樹與地點現算。
  - `created_by`：誰開的（FK `app_user`），其他種類是 NULL。
  - `archived_at`：封存的時間，只有文字頻道會有。
- `topic` 用既有的 `unit_id` 指它所在的區或根節點（`TW`），跟全國、整區頻道指的是同一個欄位。
- 約束：
  - `owner` CHECK 多一條：`topic` 的 `unit_id` 與 `name` 有值、`manager_id`／`place_id`／`customer_id` 為空；
    其他種類的 `name`、`archived_at` 一律為空。
  - `unit_id` 原本整欄唯一（每個單位只有一個頻道），改成部分唯一索引，只限 `kind IN ('national', 'region')`。
  - 同一個單位裡文字頻道不能重名：`(unit_id, lower(name))` 的部分唯一索引，只限 `kind = 'topic'`，**封存的也算**。
    要沿用舊名稱，先把舊的改名或解除封存。
- 會讀「`unit_id` 有值就是全國或整區頻道」的地方都要加上種類的條件，不然會拿到文字頻道：
  `ensure_channels` 判斷哪個單位還缺頻道、`describe` 找每個單位的頻道（`by_unit`，算上層用）。

### 名稱、路徑與上層

`describe` 對文字頻道算出：

| 欄位 | 開在區裡（例如北區） | 開在全國 |
|---|---|---|
| `name` | `channel.name` | `channel.name` |
| `path` | 區的 id，例如 `TW.N` | `TW` |
| `region_id` | 區的 id | NULL |
| `parent_id` | 北區頻道 | 全國頻道 |
| `audience` | 「北區所有人都看得到」 | 「全公司都看得到」 |
| `archived` | `archived_at` 有值 | 同左 |

**共享層級跟著所在的單位**：開在區裡用整區頻道的層級，開在全國用全國頻道的層級。`LEVEL` 原本依種類查表，
文字頻道改成依 `region_id` 有沒有值決定。

### 誰看得到

跟它所在的區或全國一樣，用同一個 `Scope.can_see`。看得到就能發言（封存的除外）。

| 帳號 | 看得到的文字頻道 |
|---|---|
| 業務 U01、主管 M01（北區） | 全國的、北區的 |
| 業務 U04、主管 M03、M04（南區） | 全國的、南區的 |
| IT | 全部 |
| 自建與第三方登入 | 跟代理的 U01 一樣 |

### 誰能開、改名、封存

`can_manage(user, info)`，只對全國、整區與文字頻道有意義：

- IT：都可以。
- 主管：沒停用，而且 `user.unit_id` 就是那一區。只能管自己這一區的整區頻道與底下的文字頻道，不能管全國的。
- 其他人都不行。自建帳號代理的是業務，也不行。

開頻道看的是「上層那個全國或整區頻道」，改名、封存看的是「文字頻道所在的區」，所以**同一區的主管都能改名、封存**，
不限原本開的那一位。

### 封存

- **不能刪除**：訊息與整理出來的記憶要留著，跟訊息不能刪同一個道理。
- 封存後**還看得到、變成唯讀**：
  - 發言回 409；記憶看板上的重點不能改、刪、撤回（`memory_board.editable` 已經擋 `archived`）。
  - 熊熊滾不回答、不整理、不發週摘要與逾期提醒（這些地方都已經跳過 `archived`）。
  - 沒有成員，不算在線人數（`presence.is_member` 已經跳過 `archived`）。
  - 已經往上傳的重點留在上層看板上。
- 可以解除封存，一切恢復。
- **跟封存的小組頻道不一樣**：小組頻道封存是因為主管不在了，只剩 IT 看得到；文字頻道封存是有人按的，
  整區照樣看得到。`can_see` 裡「封存就只有 IT」那一條改成只限 `team`。

### 紅點

`badge_count` 多算「上層在紅點範圍裡的文字頻道」：一般人是全國與自己這一區底下的，IT 是全國與三個區底下的。
封存的不算。

## API

| 方法 | 路徑 | 內容 |
|---|---|---|
| GET | `/api/channels` | 多回文字頻道（含封存的）。每一列多 `can_manage` |
| GET | `/api/channels/{id}` | 同上，多 `can_manage` |
| POST | `/api/channels` | 開文字頻道，body `{parent_id, name}`，`parent_id` 是全國或整區頻道。回 201 與新頻道 |
| PATCH | `/api/channels/{id}` | 改文字頻道，body `{name?, archived?}`。回改好的頻道 |

錯誤：

- `parent_id` 或要改的頻道看不到：404。
- `parent_id` 不是全國或整區頻道、要改的不是文字頻道：400。
- 看得到但不能管：403。
- 名稱去掉空白後是空的或超過 20 字：422。
- 同一個單位已經有同名的文字頻道：409，訊息寫「北區已經有叫「新品上市」的頻道」。

開頻道、改名、封存、解除封存 commit 之後發一則即時事件 `{"type": "channels"}`。WebSocket（`api/presence.py`）
原樣轉給每一條連線（不帶內容，看不到的頻道不會因此透露），手機端 `lib/realtime.ts` 再轉給訂閱的畫面。
頻道列表收到 `avatars` 以外的事件都會重新載入（`pages/channels.tsx`），所以大家的左右欄會自己更新。

`channel_ai.KIND_LABEL`、前端的 `KIND_LABEL` 多「文字頻道」。

## 畫面

以手機為主，跟其他頁一樣窄；電腦上也是同一個版面，置中。

### 進入點

- `/channels`：左右兩欄。底部分頁列的「頻道」、主管端與組織管理頁的「頻道」按鈕都進這裡。
- 選中哪個頻道放在網址 `?c=<頻道 id>`；網址沒有就用上次選的（`localStorage` 的 `meddemo:channel-rail`，讀寫包 try/catch），
  再沒有就是自己的小組，IT 是全國。選中的頻道已經看不到了（被封存、被調區），一樣退回預設。
- `/channels/:id` 對話頁、`/channels/:id/threads`、`/channels/search` 都不改網址，搜尋、問答出處、風險通報、
  客戶檔案的「討論串」這些現有連結照常能用。
- 對話頁的返回鍵：沒有帶 `backTo` 時回 `/channels?c=<…>`。文字頻道與客戶討論串回上層（`parent_id`），其他回自己。
  所以從右欄點進對話，按返回還停在原本那個頻道。
- 右欄點「記憶看板」進對話頁時帶 `state.tab = "board"`，直接打開看板分頁。

### 左欄

- 寬約 72px，可以捲動。每個頻道一塊 48px 的圓角方塊，上面寫兩個字，底色依頻道 id 從頭像同一組五個顏色裡挑。
- 兩個字的規則（`shortName`）：
  - 小組：主管名字的縮寫，跟頭像同一套規則（陳建宏小組 → 建宏）。
  - 地點：「・」後面那一段；去掉結尾的「區／市／縣」後還有兩個字以上就去掉，再取前兩個字
    （台北市・大安區 → 大安、新北市 → 新北、彰化縣 → 彰化）。
  - 全國、整區：照名稱（全國、北區）。
- 順序：全國 → 每一區依序放整區、各小組、一個「地點」資料夾 → IT 才有的「已封存」資料夾（封存的小組頻道）。
  區與區之間一條分隔線。
- 資料夾是一塊有 `MapPin`（地點）或 `Archive`（已封存）圖示的方塊，點了在原地展開，裡面的頻道縮排列在下面；
  資料夾裡有頻道被選中時自動展開。
- 選中的那一塊左邊有一條直的指示條、方塊換成主色外框。
- 未讀：右下角紅色數字，跟現在的 `UnreadDot` 一樣。整區與全國的數字加上底下沒封存的文字頻道；地點資料夾是裡面地點的總和。
  客戶討論串的未讀不往上加（跟現在的列表一樣，只在討論串那一列顯示）。

### 右欄

- 頁首：頻道名稱、種類與誰看得到（「整區頻道・北區所有人都看得到」）、N 人在線、成員（沿用 `ChannelMembers`）。
- 一張卡片列出：
  - **對話**（`MessagesSquare`）：有未讀顯示數字。
  - **記憶看板**（`NotebookText`）。
  - **照片與檔案**（`Images`）：進 `/channels/search?channel=<id>`。
- **文字頻道**（只有全國與整區）：
  - 標題列右邊，`can_manage` 的人有「新增頻道」（`Plus`）。
  - 一列一個文字頻道（`Hash` 圖示、名稱、最近一則的時間、在線人數、未讀數），點了進對話頁。
  - `can_manage` 的人每一列右邊多一個「管理」按鈕（`EllipsisVertical`），打開管理對話框。
  - 封存的收在最下面的「已封存（N）」，點了展開，名稱旁標「已封存」。
  - 沒有文字頻道時：能開的人看到「還沒有文字頻道，按「新增頻道」開一個」，其他人看到「還沒有文字頻道」。
- **客戶討論串**（只有地點）：直接列出有發言的討論串（`GET /api/channels/{id}/threads`），沒有時顯示現在那句提示。
  點了進對話頁，返回回到這個地點。
- 封存的小組頻道（IT）：卡片上方一句「已封存，只能看」。

### 新增與管理

- **新增頻道**對話框：名稱欄（最多 20 字）、下方一行「北區所有人都看得到，大家都能發言。」、取消／建立。
  建立成功直接進新頻道的對話頁。409（重名）與 422（名稱不對）顯示後端的訊息，說得出原因；
  其他錯誤顯示「沒有建立，請再試一次」。管理對話框同一套，通用的那句是「沒有改到，請再試一次」。
- **管理**對話框：名稱欄與「儲存」；下方「封存這個頻道」（封存的顯示「解除封存」），封存前多一句說明
  「封存後大家還看得到，但不能再發言」。

### 移除

- `pages/channels.tsx` 原本的分段列表，與只有它在用的 `lib/channels.ts` 的 `groupChannels`、`sortUnreadFirst`。
- `ChannelRow` 照舊給右欄的文字頻道、客戶討論串，以及 `/channels/:id/threads` 用。

## 示範資料

`catalog.py` 多 `TOPICS`，灌資料時建好，再照 `CONVERSATIONS` 的寫法放幾則手寫對話（新的頻道種類 `("topic", 名稱)`）：

- 北區「新品上市」：M01 開。延續既有情境，聊固循魚油新包裝上市、店家要試吃包。
- 北區「補貨問題」：M01 開。北區倉排程、一週補貨兩次之後的狀況。
- 全國「公司公告」：A01 開。月底結帳日、新版報價權限規範。

不預先整理記憶，熊熊滾第一次有人發言時整理；打開看板的空狀態照舊。

## 測試

沿用 pytest 的測試資料庫與離線的假模型。

- **describe**：三個示範文字頻道的路徑、上層、所在的區、`audience` 正確；整區、小組頻道的上層沒有被文字頻道搶走。
- **看得到**：U01 看得到北區兩個與全國一個；U04 只看得到全國那個，打北區的回 404；IT 全部看得到。
  既有測試裡頻道總數（25）與各帳號看得到的名稱跟著加上文字頻道。
- **開頻道**：M01 在北區 201；M01 在全國 403；M01 在南區 404；M03 在南區 201；U01、自建帳號 403；
  IT 在全國與中區 201；`parent_id` 是小組或地點 400；名稱空白或 21 字 422；同區同名（大小寫、前後空白不同也算）409；
  不同區同名可以。
- **改名、封存**：M01 能封存 A01 在北區開的；M03 改北區的 404；封存後 U01 還看得到、`archived` 是 true、發言 409、
  改記憶 409；解除封存後能發言。
- **紅點**：U01 的紅點算北區與全國文字頻道的未讀，不算南區的；封存的不算。
- **記憶**：文字頻道往上傳的重點出現在北區與全國的看板，撤回後都消失（`memory_board.descendants` 跟著 `parent_id`）。
- **即時事件**：開、改名、封存各發一則 `channels`。
- **ensure_channels**：有文字頻道之後重跑不會多開、也不會少開全國與整區頻道。
- **灌資料**：三個文字頻道都在，對話寫進去了。
- **前端**（vitest）：`shortName` 的規則；左欄項目的順序、地點與已封存資料夾、未讀加總；預設選哪個頻道；
  文字頻道依建立順序、封存的在後面。
- **實機**：用無頭 Chrome（假的 API）分段走：M01 進 `/channels` 選北區 → 右欄有「新增頻道」→ 開「測試頻道」→ 進到對話頁 →
  返回停在北區；U01 看不到「新增頻道」；淺色與深色各截一張圖。
- **壓力測試**：`backend/scripts/stress_channels.py` 對本機的 API：50 個帳號各開一條 WebSocket，同時在同一個文字頻道
  各發 3 則，再用 `after` 輪詢把訊息拿齊。通過條件：沒有 5xx、每個人都拿到 150 則、每條 WebSocket 都收到通知、
  發言的 p95 在 1 秒內。只打本機（`--base-url` 不是 localhost 就拒絕），不會在正式站留下測試訊息。
  第一次跑在 50 人時卡死（原本就在 main 上的問題）：請求在換執行緒之間會拿著資料庫連線，連線池（預設 15 條）
  比 threadpool（40 條）小，WebSocket 又每條連線、每個事件各查一次資料庫，兩邊互等到連線池逾時。
  修法：連線池加到 20 + 40（`app/db.py`）；每條連線連上時算好看得到的頻道、之後只查新出現的頻道；
  同一則狀態事件在同一個程序裡只查一次大家的狀態（`api/presence.py` 的 `_StatusCache`）：事件帶著 commit 之後取的時間
  （`at`），每條連線都拿它判斷，第一條開始算的那一份其他條直接共用。不能用各條連線收到事件的時間：
  連線一條接一條跑，後面那條收到的時間一定比前面那條開始算的晚，結果還是每條各查一次。

## 部署

- `models.py`、`catalog.py` 改了，`schema_version` 的指紋跟著變，部署時自動重建資料庫（跟之前一樣）。
- README 的頻道段落改成左右兩欄與文字頻道。

## 不在這次範圍

- 語音、通話、直播、錄影。
- 小組、地點底下開文字頻道；業務開頻道。
- 刪除文字頻道、調整文字頻道的順序、分類（Discord 的頻道分類）、只給部分人看的私人頻道。
- 文字頻道的圖示或顏色自訂。
- 平板與電腦的三欄版面。
