# 熊熊滾騎座騎：每段路選交通方式，各縣市一套座騎

2026-10-07

首頁的蛇行路線上，業務替每兩站之間的一段選交通方式（開車、機車、大眾運輸、走路），車程照選的方式重算。
每完成一站，熊熊滾就騎著「那個縣市 × 那種交通方式」的座騎，從這一站移到下一站。七個縣市各挑一種特產，
四種交通方式各變成一種座騎，共 28 種；騎過的收進座騎圖鑑。

## 為什麼做

- 首頁的路線只有一顆顆圓鈕，看不到一站到下一站怎麼去、要多久；車程一律照開車算。
- 業務實際跑客戶會騎機車、在台北搭捷運、近的兩家用走的。
- 決賽展示需要一個評審記得住的畫面：熊熊滾騎著貢丸進新竹。

## 已定案的決定

1. **交通方式一段一段選**，四種：開車、機車、大眾運輸、走路。預設開車。
2. **選了就真的重算**：這一段照選的方式問 Google，後面每一站的到達時間與「會晚到 N 分」跟著變。
3. **排順序仍照開車算**（每天第一次建、加一站、幫我排順一點），排好之後算時間才照每段的交通方式。
4. **交通方式記在「哪一站到哪一站」這一段上**：換順序後還相鄰的兩站保留，新相鄰的回到開車。
5. **在首頁兩站之間的膠囊上選**。調整清單只顯示、不能改。
6. **七個縣市 × 四種交通方式，一種一個座騎，共 28 種**；特產本身就是座騎（變成車身、輪子、列車）。
7. **完成一站、回到首頁時自動播一次**（約 3 秒）；今天第一次打開首頁播「辦公室 → 第 1 站」；點座騎重播。
8. **跨縣市的一段在半路冒煙換車**，頭上冒出新縣市的名字。
9. **座騎圖鑑**：騎過的有顏色，沒騎過的是剪影。騎過的記在伺服器、算在業務名下，IT 重置示範業務的行程時清掉。
10. **示範資料加新竹市**，林昱辰今天的路線經過台北、新北、新竹三個縣市。
11. **照熊熊滾的做法**：SVG 加 CSS 做成 React 元件，移動用 Web Animations API，不引入 Lottie、Rive。

## 資料

`models.py` 改了，`schema_version` 的指紋跟著變，部署時重建資料庫（跟以往一樣）。

### `itinerary_leg`：每段路怎麼去

| 欄位 | 內容 |
|---|---|
| `itinerary_id` | 哪份行程，行程刪掉時一起刪 |
| `from_customer_id` | 從哪一家出發；NULL 是從辦公室出發 |
| `to_customer_id` | 到哪一家 |
| `mode` | `two_wheeler`／`transit`／`walk` |

- `(itinerary_id, from_customer_id, to_customer_id)` 唯一，`NULLS NOT DISTINCT`（從辦公室出發的那段也只能有一列）。
- **只存不是開車的段**：沒有這一列就是開車；改回開車就刪掉那一列。
- 交通方式的值照 Google 的 `travelMode` 取小寫：`drive`、`two_wheeler`、`transit`、`walk`。
- 拿掉一站時，`from` 或 `to` 是它的列一起刪。存檔、套用提案、加一站之後，刪掉不再相鄰的列。

### `vehicle_ride`：騎過哪些座騎

| 欄位 | 內容 |
|---|---|
| `user_id` | 業務，帳號刪掉時一起刪 |
| `city` | 七個縣市之一 |
| `mode` | 四種交通方式之一 |
| `first_ridden_at` | 第一次騎的時間 |

主鍵 `(user_id, city, mode)`。IT 重置示範業務的行程時，刪掉示範業務的這些列。

### 縣市

- 客戶的縣市用現有的 `customer.city`。
- 辦公室的縣市：`org_unit` 多一個 `city`，跟 `lat`、`lng` 一樣只有北、中、南三區有值（台北市、台中市、高雄市），
  寫在 `data/seed/catalog.py` 的 `REGION_OFFICE` 旁邊。

## 車程：`services/travel.py`

| 交通方式 | 估算：繞路倍數 | 時速 | 另外加 | Google 的結果另外加 |
|---|---|---|---|---|
| 開車 | 1.4 | 30 公里 | 5 分（找車位） | 5 分 |
| 機車 | 1.4 | 32 公里 | 2 分 | 2 分 |
| 大眾運輸 | 1.4 | 18 公里 | 8 分（走到站、等車） | 不加（Google 已含走路與等車） |
| 走路 | 1.3 | 4.5 公里 | 不加 | 不加 |

- `matrix()` 不變，仍只算開車，給排順序用。
- `along(points, modes, departures)`：`modes[i]` 是 `points[i] → points[i + 1]` 這一段。
  - Google 的 `computeRoutes` 一次只能用一種交通方式，大眾運輸還不能有中途站。所以**相鄰、交通方式相同的段合成一次問**
    （帶中途站），**大眾運輸每段單獨問**，所有請求同時送出（執行緒池），各自 5 秒逾時。
  - 哪一組失敗就只有那幾段用估算，整份標 `estimated`。Google 失敗後 60 秒內不再問，跟現在一樣。
  - 大眾運輸要給出發時間：先把大眾運輸的段用估算排一次時間表（`route_planner.schedule`），拿每段的出發時間去問。
  - `routingPreference: TRAFFIC_UNAWARE` 只帶給開車與機車；大眾運輸、走路帶了 Google 會回錯。
- `options(a, b, departure)`：同一段四種交通方式各要多久，四個請求同時送；每一種各自回分鐘、公里、是不是估算、
  Google 有沒有找到路線。
- `google_routes.route_legs` 多收交通方式與出發時間兩個參數。

## API

| 方法與路徑 | 用途 |
|---|---|
| `GET /api/itinerary/today` | 每站多回 `travel_mode`（從上一站過來的方式）與 `city`；行程多回 `start_city`（辦公室的縣市）。每站的 `travel_minutes`、`travel_km` 照那一段的交通方式算 |
| `GET /api/itinerary/today/legs/options?from=&to=` | 這一段四種交通方式各要多久；沒帶 `from` 是從辦公室出發 |
| `PUT /api/itinerary/today/legs` | `{from, to, mode, version}` 改一段的交通方式，回新的行程。`version` 不對回 409；這兩家現在不相鄰回 422 |
| `POST /api/vehicles/rides` | `{rides: [{city, mode}]}` 記騎過；送兩次只記一次；不認得的縣市或交通方式回 422 |
| `GET /api/vehicles` | `{total: 28, ridden: n, items: [{city, mode, ridden_at}]}`，沒騎過的 `ridden_at` 是 null |
| `POST /api/admin/demo-itinerary/reset` | 原本的重置，多清掉示範業務的 `vehicle_ride` |

跟其他路線的 API 一樣，業務由 token 決定（`acts_as_user_id or id`）；主管與 IT 回 403「主管沒有自己的拜訪路線」。

## 首頁

### 交通方式的膠囊

- 每兩站之間的路上、兩顆圓鈕正中間放一顆膠囊：交通方式的圖示、名稱、分鐘數、往下的箭頭（「機車 11 分」）。
  估算的分鐘數前面加「約」。
- 第 1 站上面多一顆：「從辦公室 · 開車 18 分」。
- 到達的那一站已完成的段：膠囊變灰、不能點，只寫圖示與名稱（已完成的站沒有車程）。
- 圖示用 lucide：`Car`、`Motorbike`、`TrainFront`、`Footprints`。
- 每一列加高，讓膠囊不壓到圓鈕、名字與「出發」泡泡；實際高度以截圖確認。

### 選單

- 點膠囊在底下彈出選單：四種交通方式與各自的分鐘數，目前選的那一種反白。分鐘數由 `legs/options` 算，回來之前是灰色佔位條。
- Google 找不到路線的那一種寫「約 N 分 · 查不到路線，用估算」，照樣可以選。
- 最底下兩行小字：「機車、走路路線是 Google 測試版」（Google 規定要提醒）；車程的來源照現在的
  `DriveSource`，Google 算的寫「Google Maps」，估算的寫「（估計）」。
- 選了就存（`PUT legs`），後面每一站的時間立刻更新，選單收起來。409 照現在的做法提示「行程剛被改過」並重新整理。
- 點選單和膠囊以外的地方、按 Esc 收起來，跟站的小卡一樣；同時只開一個（開選單時站的小卡收起來，反之亦然）。

### 別的地方

- 調整清單每站的「車程 18 分 · 6.2 公里」改成「機車 11 分 · 3.2 公里」，不能改交通方式。
- 主管頁的總計「車程」改成「路上」。主管地圖的路線照舊畫開車的路。

## 動畫

### 什麼時候播

- 回到首頁時，「最後一個已完成的站 → 下一站」這段還沒播過就自動播。
- 今天第一次打開首頁（還沒有完成的站）時播「辦公室 → 第 1 站」：熊熊滾從路線最上面騎進來。
- 播過哪幾段記在瀏覽器的 localStorage（key 含日期與兩端的客戶），讀寫都包 try/catch；記錄不見頂多再播一次。
- 等換頁的墨退掉（`ink` 的控制器通知）、把下一站捲進畫面之後才開始。同一時間只播一段。

### 怎麼動（共約 3 秒）

1. 0.3 秒：座騎在熊熊滾腳下「啵」地冒出來，熊跳上去。
2. 2.4 秒：沿蛇行路線的彎度，從這一站旁邊移到下一站旁邊（熊熊滾平常站的位置）。路徑在畫面上量兩顆圓鈕的位置後取樣成
   Web Animations API 的關鍵影格。往左走時整組左右翻過來。
3. 0.3 秒：到了壓扁、回彈。

- **跨縣市**：走到一半冒出一團淺紫色（`#C9A2F5`）的煙，煙散開時已換成新縣市的座騎；熊頭上冒出新縣市的名字，1 秒後消失。
- **騎過的記錄**：動畫一開始就送 `vehicles/rides`（跨縣市送兩筆），中途切走也記得到。
- 播完熊熊滾坐在座騎上停在下一站旁邊，座騎慢慢上下浮。**點一下重播這一段**；原本點熊進問答頁的連結拿掉，問答從底部分頁進。
- 停著的座騎是「到下一站那段」的座騎；改了那段的交通方式，停著的座騎跟著換（不重播）。
- 全部跑完照舊：熊熊滾在終點旗子旁跳 `yay`，最後一站到收工這段不騎座騎。
- **減少動態效果**（`prefers-reduced-motion`）：不移動，熊熊滾直接坐在座騎上出現在下一站旁邊，跨縣市的段顯示目的地縣市的座騎；騎過的記錄照送。

## 座騎

### 元件

- `mascot.tsx` 把熊的身體抽成 `MascotFigure`（一個 `<g>`），`Mascot` 與座騎都用它；`Mascot` 原本的用法不變。
- 熊熊滾多一個狀態 `ride`：眼睛笑到瞇起來、張嘴，身體不另外動（由座騎晃）。`2026-09-30-mascot-design.md` 的狀態表一起補上。
- `components/rides/`
  - `ride.tsx`：`<Ride city mode size flipped />`，熊疊在座騎上（座騎擋住熊的腳）。
  - `vehicles/<縣市>.tsx`：一個縣市一個檔，各匯出四種交通方式的圖。
  - `ride.css`：輪子轉、上下浮、各縣市走路的動法；class 都以 `ride-` 開頭。
- `lib/rides.ts`：七個縣市與四種交通方式的清單、`vehicleFor(city, mode)`、一段路跨不跨縣市、這次該播哪一段（給停靠站與播過的記錄，回要播的那段或沒有）。
- 不在七個縣市裡的客戶（目前沒有）：不騎座騎，熊熊滾用 `wait` 的踏步走過去。

### 畫法

- 跟熊熊滾一樣平塗、不描邊、沒有漸層，只用圓與圓角形狀；每個縣市的特產最多另外加 3 個顏色。
- 畫布 `0 0 300 200`，座騎一律朝右，熊的大小與位置照各座騎調整。
- 四種交通方式各有固定的變法：開車是特產當車身、熊坐在裡面；機車是特產當輪子，不圓的特產當車身；
  大眾運輸是一串特產當車廂；走路是熊踩著或坐著特產前進，看特產的特性滾、彈、飄、跳、游或滑。

## 座騎圖鑑：`/rides`

- 入口：首頁路線最底下、收工旗子下面一行「座騎圖鑑 12/28」。
- 頁首「座騎圖鑑」與「已收集 12/28」；下面一個縣市一區，照台北、新北、新竹、台中、彰化、台南、高雄排，每區四張卡（手機兩欄）。
- 騎過的：有顏色、平常靜止，點一下動 3 秒；卡片下寫第一次騎的時間。
- 沒騎過的：灰色剪影、寫「還沒騎過」；點了提示「在新竹市選機車就能收集」。
- 資料來自 `GET /api/vehicles`。

## 示範資料

- `REGION_CITIES` 的北區加新竹市；`PLACES` 加地點頻道「新竹市」（`HSZ`，`TW.N`）；`DISTRICT_COORDS` 加新竹市的東區、北區、香山。
- 新增 3 家新竹市的客戶（藥局與診所都有），算在林昱辰（U01）名下；其中一家給夠強的訊號（例如承諾逾期），讓它一定排進今天的建議。
- 示範習慣「敦南內科診所 · 大安 排最後」（星期三）照舊，所以新竹那站排在下午、新北的站之後，最後回台北：
  台北 → 新北 → 新竹 → 台北，多一次跨縣市換車。
- **驗收條件**：IT 按「重置示範業務今天的行程」後，林昱辰首頁的路線依序經過台北、新北、新竹；新竹那段四種交通方式都選得到分鐘數。
  用什麼方法讓模型穩定排出這個順序，寫計畫時決定。

## 出錯時

- Google 某一組失敗或逾時：只有那幾段用估算，畫面註明「（估計）」。
- 查不到路線（例如郊區沒有公車）：選單那一列寫「約 N 分 · 查不到路線，用估算」，照樣可以選。
- `vehicles/rides` 送不出去：先存在 localStorage，下次打開首頁再送。
- 量不到圓鈕的位置（畫面還沒排好）：不播，熊熊滾直接出現在下一站旁邊，騎過的記錄照送。
- 播到一半離開首頁：取消動畫，不留殘影。
- IT 重置示範行程：行程刪掉時 `itinerary_leg` 一起刪，示範業務的 `vehicle_ride` 也清掉。

## 已知限制

- 主管地圖上的路線照舊畫開車的路，即使那一段選了走路或大眾運輸。
- 機車、走路的路線是 Google 測試版，可能缺部分道路。
- 大眾運輸的出發時間取自估算排出的時間表，跟真正的出發時間可能差幾分鐘。
- 播過哪幾段記在瀏覽器，換手機會再播一次。
- 評審共用示範業務，騎過的記錄會一直累加，要靠 IT 重置。

## 不在這次範圍

- 音效。
- 腳踏車（YouBike）與七個縣市以外的座騎。
- 在調整清單裡改交通方式。
- 記住業務常用的交通方式當預設（一律從開車開始）。
- 主管頁的座騎動畫、主管地圖照交通方式畫路線。
