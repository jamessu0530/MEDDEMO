# 熊熊滾騎座騎：每段路選交通方式，各縣市一套座騎

2026-10-07

業務的交通方式（開車、機車、大眾運輸）是整天的預設，在帳號設定或首頁地圖的按鈕改（2026-10-04 已做好，
見 [行程設計〈交通方式〉](2026-10-01-itinerary-planning-design.md)）。這次在首頁蛇行路線的兩站之間加一顆膠囊，
每一段可以另外選別的方式，多一種走路，時間照選的方式重算。每完成一站，熊熊滾就騎著「那個縣市 × 那種交通方式」的
座騎，從這一站移到下一站。七個縣市各挑一種特產，四種交通方式各變成一種座騎，共 28 種；騎過的收進座騎圖鑑。

## 為什麼做

- 整天一種交通方式不夠細：業務在台北搭捷運，到了新北改騎機車，近的兩家用走的。
- 首頁的蛇行路線看不到一站到下一站怎麼去、要多久。
- 決賽展示需要一個評審記得住的畫面：熊熊滾騎著貢丸進新竹。

## 已定案的決定

1. **業務的交通方式是整天的預設**（開車、機車、大眾運輸三種，原本就有）。**每一段可以另外選**，四種：開車、機車、
   大眾運輸、走路。走路只能單段選，不能當整天的預設。
2. **選了就真的重算**：這一段照選的方式問 Google，後面每一站的到達時間與「會晚到 N 分」跟著變。
3. **排順序照業務的預設**（每天第一次建、加一站、幫我排順一點，跟現在一樣）；排好之後算時間才照每段的交通方式。
4. **另外選的記在「哪一站到哪一站」這一段上**，只存跟預設不一樣的段：換順序後還相鄰的兩站保留，新相鄰的照預設；
   選回預設就刪掉那一列。**換整天的預設時，今天另外選的全部清掉**，整天照新的預設重算。
5. **在首頁兩站之間的膠囊上選**。調整清單只顯示、不能改。地圖上的線、站的小卡、導航連結都照每段實際的交通方式。
6. **七個縣市 × 四種交通方式，一種一個座騎，共 28 種**；特產本身就是座騎（變成車身、輪子、列車）。
7. **完成一站、回到首頁時自動播一次**（約 3 秒）；今天第一次打開首頁播「辦公室 → 第 1 站」；點座騎重播。
8. **跨縣市的一段在半路冒煙換車**，頭上冒出新縣市的名字。
9. **座騎圖鑑**：騎過的有顏色，沒騎過的是剪影。騎過的記在伺服器、算在業務名下，IT 重置示範業務的行程時清掉。
10. **示範資料加新竹市**，林昱辰今天的路線有一站在新竹市（前一站在新北市），也有台北市的站。
11. **照熊熊滾的做法**：SVG 加 CSS 做成 React 元件，移動用 Web Animations API，不引入 Lottie、Rive。

## 交通方式的值

| 值 | 畫面 | Google `travelMode` | 整天預設 | 單段 |
|---|---|---|---|---|
| `drive` | 開車 | `DRIVE` | 可以 | 可以 |
| `scooter` | 機車 | `TWO_WHEELER`（測試版） | 可以 | 可以 |
| `transit` | 大眾運輸 | `TRANSIT` | 可以 | 可以 |
| `walk` | 走路 | `WALK`（測試版） | 不行 | 可以 |

- 後端：`google_routes.TravelMode` 是四種（單段用）；`models.TRAVEL_MODES` 照舊是三種（`app_user.travel_mode` 的 CHECK），
  `models.LEG_MODES` 是四種（`itinerary_leg.mode` 的 CHECK）。
- 前端：`TRAVEL_MODES`（三種，設定頁與地圖按鈕）與 `LEG_MODES`（四種，膠囊選單）放在 `lib/travel-mode.ts`，
  字、圖示（`Car`、`Motorbike`、`TrainFront`、`Footprints`）、導航用的 `travelmode`（走路是 `walking`）也都在那裡。

## 資料

`models.py` 改了，`schema_version` 的指紋跟著變，部署時重建資料庫（跟以往一樣）。

### `itinerary_leg`：跟預設不一樣的段

| 欄位 | 內容 |
|---|---|
| `itinerary_id` | 哪份行程，行程刪掉時一起刪 |
| `from_customer_id` | 從哪一家出發；NULL 是從辦公室出發 |
| `to_customer_id` | 到哪一家 |
| `mode` | 四種之一（`LEG_MODES`）；預設是機車時也可以存 `drive` |

- `(itinerary_id, from_customer_id, to_customer_id)` 唯一，`NULLS NOT DISTINCT`（從辦公室出發的那段也只能有一列）。
- 一段的交通方式 = 有這一列就用它，沒有就用業務的預設。
- 拿掉一站、存檔、套用提案、加一站、三顆鈕之後，刪掉不再相鄰的列。換整天的預設（`set_travel_mode`）時刪掉今天這份行程的全部列。

### `vehicle_ride`：騎過哪些座騎

| 欄位 | 內容 |
|---|---|
| `user_id` | 業務，帳號刪掉時一起刪 |
| `city` | 七個縣市之一 |
| `mode` | 四種交通方式之一 |
| `first_ridden_at` | 第一次騎的時間 |

主鍵 `(user_id, city, mode)`。IT 重置示範業務的行程時，刪掉示範業務的這些列。

### 縣市與辦公室

- 客戶的縣市用現有的 `customer.city`。
- 辦公室的縣市：`org_unit` 多一個 `city`，跟 `lat`、`lng` 一樣只有北、中、南三區有值（台北市、台中市、高雄市），
  寫在 `data/seed/catalog.py` 的 `REGION_OFFICE` 旁邊。
- 行程多回 `office_start`：今天是不是從辦公室出發（區處有位置）。組織管理新開的區沒有位置時是 false：第一段的膠囊不顯示、
  不播「辦公室 → 第 1 站」。縣市與經緯度是分開的欄位，不能拿 `start_city` 代替。

## 車程：`services/travel.py`

估算（`PACES`）與 Google 的結果另外加的分鐘（`GOOGLE_EXTRA_MINUTES`）：

| 交通方式 | 繞路倍數 | 速度 | 估算另外加 | Google 另外加 |
|---|---|---|---|---|
| 開車 | 1.4 | 時速 30 | 5 分（找車位） | 5 分 |
| 機車 | 1.3 | 時速 28 | 2 分 | 2 分 |
| 大眾運輸 | 1.3 | 時速 20 | 10 分（走到站、等車、轉乘） | 不加（Google 已含走路與等車） |
| 走路 | 1.3 | 時速 4.5 | 不加 | 不加 |

前三種是 2026-10-04 定的，這次只加走路。

- `matrix(points, mode)` 不變，用業務的預設，給排順序用。
- `along(points, modes)`：`modes[i]` 是 `points[i] → points[i + 1]` 這一段的交通方式（也接受一種，整條都用它）。
  - Google 一次只能問一種交通方式。**相鄰、交通方式相同的段合成一組**（開車、機車、走路帶中途站一次問；大眾運輸照舊在
    `google_routes` 裡一段一段問），**各組同時送出**。
  - 哪一組失敗就只有那幾段用估算，並暫停問 Google 60 秒（跟現在一樣）；大眾運輸搭不到車的段用估算、不暫停。
  - 同一個點的兩站（同一棟樓、區處沒有位置時的第一段）不問 Google，0 分鐘。
  - 回的 `Matrix` 多 `estimated_legs`：每一段是不是估算的，畫面上每段各自決定要不要加「約」。
- `lines(points, modes)`：地圖沿路的線也照每段的交通方式，同樣分組問；快取的鍵含每段的交通方式。
- `options(a, b)`：同一段四種交通方式各要多久，四個請求同時送；每一種回分鐘、公里、是不是估算、Google 有沒有找到路線。
- 大眾運輸的出發時間照現在的做法：今天早上 10 點。

## API

| 方法與路徑 | 用途 |
|---|---|
| `GET /api/itinerary/today` | 每站多回 `travel_mode`（這一段實際用的）、`travel_estimated`、`city`；行程多回 `start_city`、`office_start`。`travel_mode`（整天的預設）照舊 |
| `GET /api/itinerary/today/legs/options?from=&to=` | 這一段四種交通方式各要多久；沒帶 `from` 是從辦公室出發 |
| `PUT /api/itinerary/today/legs` | `{from, to, mode, version}` 改一段的交通方式（`from` 一定要帶，可以是 null），回新的行程。`version` 不對回 409；不是還沒走的一段回 422 |
| `PUT /api/itinerary/travel-mode` | 原本的換整天的預設，多清掉今天另外選的段 |
| `GET /api/itinerary/today/map`、主管的兩支 | 線與站的小卡照每段的交通方式 |
| `POST /api/vehicles/rides` | `{rides: [{city, mode}]}` 記騎過；送兩次只記一次；不認得的縣市或交通方式回 422 |
| `GET /api/vehicles` | `{total: 28, ridden: n, items: [{city, mode, ridden_at}]}`，沒騎過的 `ridden_at` 是 null |
| `POST /api/admin/demo-itinerary/reset` | 原本的重置，多清掉示範業務的 `vehicle_ride` |

跟其他路線的 API 一樣，業務由 token 決定（`acts_as_user_id or id`）；主管與 IT 回 403「主管沒有自己的拜訪路線」。

## 首頁

### 交通方式的膠囊（蛇行路線）

- 每兩站之間的路上、兩顆圓鈕正中間放一顆膠囊：交通方式的圖示、名稱、分鐘數、往下的箭頭（「機車 11 分」）。
  估算的段（`travel_estimated`）分鐘數前面加「約」。
- 第 1 站上面多一顆：「從辦公室 · 開車 18 分」；`office_start` 是 false 時不顯示。
- 到達的那一站已完成的段：膠囊變灰、不能點，只寫圖示與名稱（已完成的站沒有車程）。
- 下一站那一列再多留一點高度，膠囊不壓到「出發」泡泡（以截圖確認）。
- 路線底下：只要有一段還沒走的是 Google 算的（`travel_estimated` 是 false），就寫一行「Google Maps」（Roboto、不翻譯）。

### 選單

- 點膠囊在底下彈出選單：四種交通方式與各自的分鐘數，目前用的那一種反白，整天的預設那一列旁邊標「整天預設」。
  分鐘數由 `legs/options` 算，回來之前是灰色佔位條。
- Google 找不到路線的那一種寫「約 N 分 · 查不到路線，用估算」，照樣可以選。
- 最底下：「機車、走路路線是 Google 測試版」（Google 規定要提醒）；只要有一種是 Google 算的就寫「Google Maps」，四種都是估算才寫「（估計）」。
- 選了就存（`PUT legs`），後面每一站的時間立刻更新，選單收起來。409、422 提示並重新載入。
- 點選單和可以點的膠囊以外的地方、按 Esc 收起來；同時只開一個（開選單時站的小卡收起來，反之亦然）。
- 用的是手機上的舊行程、或正在存的時候，膠囊不能點。

### 首頁地圖與其他地方

- 地圖上的線照每段的交通方式畫（大眾運輸的走路虛線照舊）；地圖左上角換整天的預設照舊，換了今天另外選的清掉。
- 地圖的站卡寫那一段實際的交通方式（「機車約 11 分」），導航連結用那一段的交通方式。
- 頁首「· 開車」寫的是整天的預設，照舊。帳號設定的交通方式底下加一行「每一段可以在首頁另外選」。
- 調整清單每站的「車程 18 分 · 6.2 公里」改成「機車 11 分 · 3.2 公里」；整條的「車程」改成「路上」（調整清單、提案對照卡、主管頁）。
- 手機上存的舊格式行程（沒有每段的交通方式）讀出來時補上預設值，不讓首頁整頁空白。

## 動畫

### 什麼時候播

- 回到首頁時，「最後一個已完成的站 → 下一站」這段還沒播過就自動播。
- 今天第一次打開首頁（還沒有完成的站、`office_start` 是 true）時播「辦公室 → 第 1 站」：熊熊滾從路線最上面騎進來。
- 播過哪幾段記在瀏覽器的 localStorage（key 含日期與兩端的客戶），讀寫都包 try/catch；記錄不見頂多再播一次。
- 等換頁的墨退掉（`ink` 的控制器通知）、把下一站捲進畫面之後才開始。同一時間只播一段。只在路線分頁播，地圖分頁不播。

### 怎麼動（共約 3 秒）

1. 0.3 秒：座騎在熊熊滾腳下「啵」地冒出來，熊跳上去。
2. 2.4 秒：沿蛇行路線的彎度，從這一站旁邊移到下一站旁邊（座騎平常停的位置）。路徑在畫面上量兩顆圓鈕的位置後取樣成
   Web Animations API 的關鍵影格。往左走時整組左右翻過來，到站壓扁的那一刻才轉回面向圓鈕。
   辦公室 → 第 1 站：從第 1 站正上方、膠囊那一列底下冒出來，控制點在停的那一側，不壓過圓鈕。
3. 0.3 秒：到了壓扁、回彈。

- **跨縣市**：走到一半（1.5 秒）冒出一團淺紫色（`#C9A2F5`）的煙，煙散開時已換成新縣市的座騎；熊頭上冒出新縣市的名字，1 秒後消失。
  換車是疊著兩台座騎（出發縣市、目的地縣市），在 1.5 秒那一刻各做一次 opacity 的 step 切換（煙最濃、蓋住整台）。
- **騎過的記錄**：動畫一開始就送 `vehicles/rides`（跨縣市送兩筆），中途切走也記得到。
- 停的位置（`lib/ride-on-route.ts`）：下一站圓鈕沒有名字的那一側（置中或偏左停左邊，偏右停右邊）、離圓鈕 10px、
  面向圓鈕（停左邊不翻、停右邊翻）；寬 84～120px，由那一側從圓鈕邊到路線邊的空間減 4px 決定；
  座騎畫布的地面線（y=187，框的 93.5%）對齊圓鈕底邊，所以框的上緣可能比那一列高。
- 動畫做在包住座騎的外層按鈕上，用 Web Animations API，`transform-origin` 是著地點；不碰座騎的 SVG（它的位置與翻面是 SVG 的
  transform 屬性，對 SVG 元素做 CSS／WAAPI transform 會把屬性蓋掉）。停著時的上下浮也在外層；左右翻在包住座騎的一層。
  只用 transform 與 opacity。
- 同一時間只播一段，播的時候再點不理；播完回到原位，不會有兩隻熊。要自動播的那一段在開始前先藏起來（opacity 0、
  不能聚焦、不被讀出來），分頁在背景時等回到前景才開始，不記播過、不送記錄。
- 播完熊熊滾坐在座騎上停在下一站旁邊，座騎慢慢上下浮。**點一下重播這一段**；原本點熊進問答頁的連結拿掉，問答從底部分頁進。
- 停著的座騎是「到下一站那段」的座騎；改了那段的交通方式（或整天的預設），停著的座騎跟著換（不重播）。
- 全部跑完照舊：熊熊滾在終點旗子旁跳 `yay`，最後一站到收工這段不騎座騎。
- **減少動態效果**（`prefers-reduced-motion`）：不移動，熊熊滾直接坐在座騎上出現在下一站旁邊，跨縣市的段顯示目的地縣市的座騎；騎過的記錄照送。

## 座騎

### 元件

- `mascot.tsx` 把熊的身體抽成 `MascotFigure`（一個 `<g>`），`Mascot` 與座騎都用它；`Mascot` 原本的用法不變。
- 熊熊滾多一個狀態 `ride`：眼睛笑到瞇起來、張嘴，身體不另外動（由座騎晃）。`2026-09-30-mascot-design.md` 的狀態表一起補上。
- `components/rides/`
  - `ride.tsx`：`<Ride city mode size flipped still label />`，熊疊在座騎上（座騎擋住熊的腳）。
  - `vehicles/<縣市>.tsx`：一個縣市一個檔，各匯出四種交通方式的圖；`vehicles/index.ts` 收成 `VEHICLES`（`Record<RideCity, CityVehicles>`，`ride.tsx` 用 `VEHICLES[city][mode]` 直接查；不包成函式，react-hooks 的 lint 不讓 render 時畫出函式回傳的元件）。
  - `ride.css`：輪子轉、上下浮、各縣市走路的動法；class 都以 `ride-` 開頭。
- `lib/rides.ts`：七個縣市的清單、特產、`rideCity`（不在七個縣市裡是 null）。「一段路跨不跨縣市」「這次該播哪一段」
  （給停靠站與播過的記錄，回要播的那段或沒有）第三階段接上首頁時再加進去。
  交通方式的清單用 `lib/travel-mode.ts` 的 `LEG_MODES`。
- 不在七個縣市裡的客戶（目前沒有）：不騎座騎，熊熊滾用 `wait` 的踏步走過去。

### 畫法

- 跟熊熊滾一樣平塗、不描邊、沒有漸層，只用圓與圓角形狀；每個縣市的特產最多另外加 3 個顏色。
- 畫布 `0 0 300 200`，座騎一律朝右，熊的大小與位置照各座騎調整。
- 四種交通方式各有固定的變法：開車是特產當車身、熊坐在裡面；機車是特產當輪子，不圓的特產當車身；
  大眾運輸是一串特產當車廂；走路是熊踩著或坐著特產前進，看特產的特性滾、彈、飄、跳、游或滑。

| 縣市 | 開車 | 機車 | 大眾運輸 | 走路 |

## 座騎圖鑑：`/rides`

- 入口：首頁路線最底下、收工旗子下面一行「座騎圖鑑 12/28」。
- 頁首「座騎圖鑑」與「已收集 12/28」；下面一個縣市一區，照台北、新北、新竹、台中、彰化、台南、高雄排，每區四張卡（手機兩欄）。
- 騎過的：有顏色、平常靜止，點一下動 3 秒；卡片下寫第一次騎的時間。
- 沒騎過的：灰色剪影（在包住座騎的一層用 CSS `filter` 做，不改座騎）、寫「還沒騎過」；點了提示「在新竹市選機車就能收集」。

## 示範資料

- `REGION_CITIES` 的北區加新竹市；`PLACES` 加地點頻道「新竹市」（`HSZ`，`TW.N`）；`DISTRICT_COORDS` 加新竹市的東區、北區、香山。
- 新增 3 家新竹市的客戶（`catalog.HSINCHU_CUSTOMERS`：竹安藥局 · 東區、風城內科診所 · 城隍廟、濱海藥局 · 香山），
  算在林昱辰（U01）名下。編號接在原本 250 家之後（C251～C253），由 `generate.build_hsinchu` 在所有資料之後另外產生、
  用自己的亂數（`seed + 3`），拜訪只排在他那天還不到五家的平日：原本的客戶、交易、帳款、拜訪與單號一筆都不變。
- 風城內科診所（A 級）最近 50 天沒去、也沒再進貨，排序模型給的分數比他其他客戶都高，一定排進今天的建議，理由是「很久沒進貨」。
  不用承諾逾期：那會被硬排到前面、變成「需立即處理」，搶走鎖在第一站的福安連鎖藥局 · 板橋店。
- 「需立即處理」的板橋店在新北、一定排第一，所以路線不會「依序」經過台北、新北、新竹。測試環境（直線估算）排出來是
  板橋店（新北）→ 忠孝店（台北）→ 林口店（新北）→ 鶯歌店（新北）→ 風城內科診所（新竹），從新北騎進新竹那一段半路換車。
- **驗收條件**（`backend/tests/test_demo_hsinchu.py`）：IT 按「重置示範業務今天的行程」後，林昱辰今天的路線有一站在新竹市，
  而且那一站的前一站在新北市；路線裡也有台北市的站；「需立即處理」那家照舊是第一站。新竹那段四種交通方式都選得到分鐘數。

## 出錯時

- Google 某一組失敗或逾時：只有那幾段用估算，那幾段加「約」。
- 查不到路線（例如郊區沒有公車）：選單那一列寫「約 N 分 · 查不到路線，用估算」，照樣可以選。
- 手機上的舊格式行程：補預設值，不整頁空白。
- `vehicles/rides` 送不出去（連不上、5xx）：先存在 localStorage，下次打開首頁再送；4xx（422、403）是這批資料有問題，丟掉不重送。讀 localStorage 的佇列時只留縣市與交通方式都合法的項目。
- 量不到圓鈕的位置（畫面還沒排好）：不播，熊熊滾直接出現在下一站旁邊，騎過的記錄照送。
- 播到一半離開首頁：取消動畫，不留殘影。
- IT 重置示範行程：行程刪掉時 `itinerary_leg` 一起刪，示範業務的 `vehicle_ride` 也清掉，交通方式回到開車（原本就會）。

## 測試

後端（pytest）：

- 走路的估算與 Google 另外加的分鐘；四種交通方式的表對得起來（`PACES`、`GOOGLE_EXTRA_MINUTES`、`google_routes.TRAVEL`、`LEG_MODES`）。
- `along` 與 `lines` 的分組：相同交通方式的相鄰段合成一次、各組同時送、同一點不問；某一組失敗只有那幾段用估算並暫停，搭不到車不暫停。
- 一段的交通方式＝另外選的或預設；選回預設刪掉那一列；換整天的預設清掉今天另外選的。
- 換順序後還相鄰的段保留、新相鄰的照預設；拿掉一站、加一站、三顆鈕之後刪掉不再相鄰的段；不照順序跑完時用的是「最後完成的站 → 下一站」。
- 到達的那家已完成的段不能改（422）；從最後完成的站出發的段可以改；已完成的站帶著那段的交通方式。
- `PUT legs`：舊的 `version` 回 409，不是還沒走的一段回 422，少了 `from` 回 422；存了之後後面每站的時間跟著變。
- `legs/options` 四種都有；Google 找不到某一種時那一種標估算、`found` 是 false。
- 地圖與主管的線照每段的交通方式問 Google。
- `office_start`：區處沒有位置時是 false。
- `vehicles/rides` 送兩次只記一次；`vehicles` 回 28 種；主管打這些 API 回 403。
- IT 重置後示範業務的騎過記錄清空，林昱辰今天的路線有一站在新竹市、它的前一站在新北市，也有台北市的站（見〈示範資料〉驗收條件）。

前端（vitest，`renderToStaticMarkup`）：

- `lib/travel-mode.ts`：兩組清單、字、圖示、導航用的值對得起來。
- 首頁的膠囊：交通方式與分鐘數、估算加「約」、已完成的段不能點、沒有辦公室起點時不顯示第一顆、舊格式的站不會壞。

## 已知限制

- 機車、走路的路線是 Google 測試版，可能缺部分道路。
- 大眾運輸一律用今天早上 10 點的班次，跟真正出發的時間無關（沿用 2026-10-04 的做法）。
- 播過哪幾段記在瀏覽器，換手機會再播一次。
- 評審共用示範業務，騎過的記錄會一直累加，要靠 IT 重置。

## 不在這次範圍

- 音效。
- 腳踏車（YouBike）與七個縣市以外的座騎。
- 在調整清單裡改交通方式。
- 走路當整天的預設。
- 主管頁的座騎動畫。
