# SAP 人員主檔與新人第一週

2026-09-30 ｜ 會議意見 3「可以從 SAP 知道你是哪區、會賣什麼藥、新人第一週要知道什麼」｜總覽見 `2026-09-30-meeting-gaps-overview.md`

新人登入之後，有一頁告訴他：你在哪一區、主管是誰、負責哪些產品線、先認識哪幾家客戶，以及第一週每天做什麼。
「你是誰、賣什麼」來自模擬 SAP 的人員主檔；其他都是系統裡現成的資料，現查現列。

## 為什麼做

- 現在的首次使用引導只講三個操作（看路線、錄音、問答），每個人看到的都一樣，沒有「你自己的」資料。
- 新人最先要知道的三件事——哪一區、賣什麼、先找誰——散在客戶清單、品項表、組織管理頁，沒有一個地方一次看完。

## 已定案的決定

1. **模擬 SAP 多一張人員主檔**，存到職日與負責產品線。
2. **轄區不另外存一份**：哪一區、主管是誰照舊看組織樹（組織樹就是從 SAP 的組織資料來的那一份）。
   人員主檔再存一次區，IT 在組織管理頁調動之後兩邊就會對不上。
3. **新人的定義**：到職 30 天內（系統日比到職日）；沒有人員主檔的自建與第三方登入帳號一律當新人——
   決賽評審用自己的帳號登入，看到的就是新人的畫面，資料是代理的示範業務林昱辰的。
4. **第一週的內容是人寫的**，放設定檔 `backend/app/resources/first_week.json`；頁面上的數字現查。不讓 AI 生成。
5. **勾選進度存手機**（localStorage），跟首次使用引導一樣，不上伺服器。

## 資料模型

`sap_employee`（模擬 SAP 的人員主檔）

| 欄位 | 說明 |
|---|---|
| `user_id` | 主鍵，FK `app_user`，帳號刪除時一起刪 |
| `employee_no` | SAP 人員編號，`E` 加五碼，唯一 |
| `hire_date` | 到職日 |
| `product_lines` | 負責的產品線，值是品項表的類別（保健品、慢性處方、一般用藥、醫材） |

- 灌資料：五位業務與四位主管各一列（`catalog.SAP_EMPLOYEES`），到職日都在一年以前——他們在假資料裡有一整年的拜訪紀錄。
  業務的產品線四條都有（他們名下的客戶四類都在進）；IT 帳號沒有。
- IT 在組織管理頁**新增業務帳號**時同時建一列：人員編號接著最大號往下編、到職日是系統日、
  產品線取同一位主管底下其他業務的聯集，主管底下還沒有人就是全部類別。這個帳號登入就是「到職第 1 天」的新人。
- 自建與第三方登入的帳號沒有這一列。

## 新人第一週頁

`/first-week`，業務帳號都打得開（不是新人也能回來看）。主管與 IT 沒有這一頁。由上到下：

1. **你的資料**（標明來自 SAP 人員主檔）：人員編號、到職日與到職第幾天、營業所（哪一區）、直屬主管、
   轄區縣市（名下客戶所在的縣市）、名下客戶幾家（依類型、依等級）。
   自建帳號沒有人員編號與到職日，改寫一句「你看的是示範業務林昱辰的資料」。
2. **你賣什麼**：每條產品線一區——有幾個品項、同一區近 90 天進貨金額最高的三個品項（名稱、建議售價、
   業務口語的叫法）。下面一列「這個月的促銷：N 個品項」連到促銷頁；沒有進行中的促銷就不顯示。
3. **先認識這五家**：名下 A 級客戶裡近 90 天進貨金額最高的五家（不足五家用 B 級補），
   每家列類型、縣市、近 90 天進貨金額，點了進客戶檔案。
4. **第一週每天做什麼**：五天，每天三件左右的事，各自連到 App 裡對應的頁面或必讀文件，可以打勾。
   標題列顯示完成幾件。
5. **必讀文件**：設定檔列出的幾份內部文件，點了打開文件內容。

### `first_week.json`

```json
{
  "days": [
    {"day": 1, "title": "認識自己的轄區",
     "tasks": [{"id": "d1-customers", "text": "把名下的客戶清單看過一遍", "to": "/customers"},
               {"id": "d1-doc-visit", "text": "讀《拜訪紀錄》", "doc": "09-拜訪紀錄.md"}]}
  ],
  "documents": ["04-報價權限.md", "09-拜訪紀錄.md"]
}
```

五天的主題：認識轄區（客戶清單、拜訪紀錄與新客戶建檔的規定）→ 認識產品（產品線、這個月的促銷、報價權限）→
跟著路線跑一趟（今日路線、挑一家 A 級客戶看客戶檔案與談判卡、看方法卡）→ 自己錄第一筆拜訪（語音記錄、確認五個欄位）→
會問會查（問一題數字、一題規定、一題促銷；查不到轉給主管；到小組頻道打招呼）。
`to` 是 App 內的路徑，`doc` 是 `data/documents/` 的檔名；`id` 改了等於新的一件事，舊的勾選不會帶過來。
「看方法卡」連到 `/methods`，那一頁由方法卡那一項提供，四項合併後才連得到。

### 讀內部文件

必讀文件要打得開，但系統現在沒有「看一份文件」的畫面（文件只在問答的出處裡出現）。加一個最小的：

- `GET /api/documents/{source_name}`：回文件標題與每個小節的標題、內文，從 `document_chunk` 讀；找不到 404。登入就能讀——
  這些文件本來就是全公司問答查得到的內容。
- 頁面 `/documents/:sourceName`：標題加各小節，純文字。

## API

| 方法 | 路徑 | 內容 |
|---|---|---|
| GET | `/api/first-week` | 整頁的資料（下面）。主管與 IT 403 |
| GET | `/api/first-week/status` | `is_newcomer`、`day_no`，首頁決定要不要顯示入口用；主管與 IT 回 `is_newcomer: false` |
| GET | `/api/documents/{source_name}` | 一份內部文件的小節 |

`/api/first-week` 回：

- `is_newcomer`、`day_no`（到職第幾天，到職日當天是 1；自建帳號是 null）
- `employee`：`employee_no`、`hire_date`、`region`、`manager_name`、`cities`、`proxy_of`（自建帳號代理誰，其他是 null）
- `customers`：`total`、`by_type`、`by_grade`
- `product_lines`：每條 `category`、`sku_count`、`top`（`sku`、`name`、`unit_price`、`aliases`）
- `promotion`：進行中那一期的名稱與品項數，沒有是 null
- `key_customers`：`id`、`name`、`type`、`grade`、`city`、`amount_last_90d`
- `days`、`documents`（設定檔的內容；文件附上標題）

規則放 `backend/app/services/first_week.py`，路由放 `backend/app/api/first_week.py`。
客戶與進貨金額照登入者的範圍算：名下客戶用代理的那位業務（`Scope.for_user(user).acting_user_id`），
同區的進貨排名是 `sales_figures` 那一級（同一個轄區），沒有超出他本來就看得到的資料。

## 入口

- **首頁**：新人（`is_newcomer`）在路線上方多一張卡「新人第一週 · 到職第 3 天 · 完成 4／15」，點了進那一頁。不是新人不顯示。
- **帳號設定**：業務帳號多一列「新人第一週」，隨時可以回去看。
- 首次使用引導不變。

## 錯誤處理

- `first_week.json` 列的文件在索引裡找不到：那一份不列，log 記一筆；一個測試確認設定檔列的文件都存在。
- 名下沒有客戶（IT 剛開的業務帳號）：客戶那兩區寫「名下還沒有客戶，等主管分配」，其餘照常。
- 首頁問不到 `status`：不顯示那張卡，不影響路線。

## 測試

- **人員主檔**：灌資料後五位業務與四位主管各一列、IT 沒有；IT 新增業務帳號後多一列，到職日是系統日、產品線是同組的聯集。
- **新人判斷**：林昱辰不是新人；IT 新開的業務是新人、到職第 1 天；自建帳號是新人、`day_no` 是 null、`proxy_of` 是林昱辰；
  主管問 `status` 是 false、開整頁 403。
- **內容**：產品線的前三名是同一區的進貨排名、品項都屬於那個類別；先認識的五家都是登入者名下的客戶；
  沒有客戶的帳號不出錯。
- **設定檔**：五天都有事情、`id` 不重複、`doc` 與 `documents` 列的檔名都在 `data/documents/` 裡。
- **文件**：讀得到小節；不存在的檔名 404；沒登入 401。
- **前端**（vitest）：勾選進度的存取與完成數。

## 不在這次範圍

- 主管看新人的進度（進度只存在新人自己的手機）。
- IT 在畫面上指派或修改產品線、到職日。
- 依產品線限制業務看得到的品項或促銷。
- 原型裡的「AI 資深業務對練」。
- 帶出新人必看的方法卡：四項都合併後另外做（見方法卡的設計文件）。
